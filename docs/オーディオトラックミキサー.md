# オーディオトラックミキサー（ブランチ feat/track-mixer）

レイヤー（Track）単位の音量フェーダー・パン・ミュート・ソロを 1 枚のシートで操作する機能。
クリップ自身の音量（`Clip.volume` とキーフレーム）・パンとは競合せず、ミックスの最後に「トラックゲイン段」を 1 段足す形で実装した。
トラックの設定が無い（全レイヤー既定の）プロジェクトは、保存形式も出力サンプルも従来と変わらない。

## 使い方

### 開き方

メニューの「出力」▸「トラックミキサー…」（`AppCommand.trackMixer`、「ラウドネスを測る…」の隣）。
ショートカットは持たない。編集できる状態（`canEdit`）のときだけ選べる。

### 各操作

シートにはプロジェクトの全レイヤーが 1 行ずつ並ぶ（映像レイヤーも含む。動画クリップの音に効くため）。

- 音量フェーダー: 0〜2（線形）。右に dB 表示（`+0.0 dB` 形式。0 は下限 −60 dB 以下として「−∞ dB」）。中央付近の 1.0 が等倍（0 dB）。
- パン: −1〜1。右に「左 30」「中央」「右 30」のように表示（絶対値の百分率）。
- ミュート: トグル。ミュート中の行は表示を薄くする。
- ソロ: トグル。レイヤー欄のソロと同じ状態を共有する。ソロがあるときはソロのレイヤーだけが鳴る。
- リセット: その行だけ音量・パン・ミュート・ソロをすべて既定に戻す。すでに既定なら何も起きない（Undo も積まない）。
- 閉じる: Esc でも閉じる。

ミュートとソロが競合した場合は、既存の `Project.isAudible` どおりミュートが優先される。
クリップ自身の音量・パンはそのまま効き、トラックの設定はそれに掛け合わさる（クリップ 0.5 × トラック 0.5 は 0.25 倍相当）。

### Undo の単位

- 音量・パンのスライダー: ドラッグ 1 回で Undo 1 回。ドラッグ中は `beginGesture` / `updateGesture`（`liveTrackVolume` / `liveTrackPan`）で動かして Undo に積まず、離したときに `commitGesture`（「レイヤーの音量」「レイヤーのパン」）で 1 回にまとめる。
- ミュート・ソロ・リセット: それぞれ 1 操作で Undo 1 回（「レイヤーの消音」「レイヤーのソロ切り替え」「レイヤーのミックスをリセット」）。
- プロジェクトがロック中（`isLocked`）のときは編集しない。

## 設計

### モデルと保存形式（`Sources/MovieCutCore/Project.swift`）

`Track` に `volume: Double?`（キー `volume`）と `pan: Double?`（キー `pan`）を追加した。

- `nil` が既定（音量 1.0・パン 0）。`encode(to:)` は `encodeIfPresent` なので、未設定のレイヤーにはキー自体が書かれない。既存プロジェクトの保存内容は変わらず、古いアプリが読んでも既知でないキーが増えない。
- 読み込みは `Lenient.double` 。型が違って読めなかった値は捨てずに `extra` へ退避して書き戻す（`locked` / `solo` / `height` と同じ作法）。`knownKeys` にも追加済み。
- 読み出し側の computed: `trackVolumeOrDefault`（未設定・有限でない値は 1、0〜2 に丸め）、`trackPanOrDefault`（未設定・有限でない値は 0、−1〜1 に丸め）、`hasTrackMix`。
- 編集は `LayerEditing`（`LayerEditing.swift`）に集約: `setMuted` / `setTrackVolume` / `setTrackPan` / `resetTrackMix`。値を範囲に丸め、既定値（音量 1、パン 0）になったら `nil` を書いてキーを消す。`extra` の同名キーも掃除する。変わらなければ `nil` を返す。
- アプリ側のシート用メソッドは `Sources/MovieCut/ProjectModel+TrackMixer.swift`（`setTrackVolume` / `setTrackPan` / `toggleTrackMuted` / `toggleTrackSolo` / `resetTrackMix`）。UI は `TrackMixerSheet.swift`、表示フラグは `ProjectModel.showTrackMixerSheet`。

### TrackMixer.swift の役割（`Sources/MovieCutCore/TrackMixer.swift`）

UI にもミックスにも依存しない純粋ロジック。

- `TrackMix`: `gain`（線形 0〜2）と `pan`。`TrackMix.of(_:)` で `Track` から作り、`identity`（1, 0）と `isIdentity` を持つ。`stereoGains` は `gain × AudioPan.gains(pan)`（等パワーの左右別倍率）。dB 変換は `db(forGain:)`（`20·log10`、0 以下は下限 `minDb` = −60）と `gain(forDb:)`（−60 以下は 0）。
- `TrackMixGains`: 左右別の `Float` 倍率（`l`, `r`）。`multiplied(by:)` は要素ごとの乗算で、入れ子の合成に使う。
- `TrackMixer.audibleTracks(in:)`: `project.tracks` と同じ順で `isAudible` の結果を返す（ミュート・ソロの解決は既存の `isAudible` が正）。

### ミックス段の位置（`Sources/MovieCutCore/AudioMixer.swift`）

`mixdownDetailed` の対象列を `CompoundEditing.audibleClipsWithTrackMix` に切り替え、`Item` に `trackL` / `trackR`（既定 1）を持たせた。
トラックゲインは、クリップ音量（キーフレーム含む）・フェード・クリップパン・ダッキング・ノーマライズ倍率をすべて掛けた後の最終段で、左右別に掛ける。3 つの経路すべてに同じ最終段がある。

- 速い道でない経路（音量キー・エフェクト・パン・ダッキングのいずれかあり）: `tL[k] * fg * pl * it.trackL` / `tR[k] * fg * pr * it.trackR`。
- フェードのみの経路: `tL[k] * fg * it.trackL` / `tR[k] * fg * it.trackR`。
- 素通りの速い道: ループの前に `gl = g * it.trackL`、`gr = g * it.trackR` を作り、`tL[k] * gl` / `tR[k] * gr` とする（既存の `tL[k] * g` の `g` を左右別にしただけ）。

`plain` の判定自体は従来のまま。トラックゲインが identity でないクリップも、速い道のまま左右別の倍率で処理できる。

### 入れ子の合成（`Sources/MovieCutCore/Compound.swift`）

`CompoundEditing.audibleClipsWithTrackMix(in:)` が、平らにしたクリップに `TrackMixGains` を添えて返す。既存の `audibleClips(in:)` は挙動もシグネチャも変えず、新しい `flatten`（mix 引数付き）に identity で委譲している。

- トップレベル: `isAudible` なレイヤーだけ、その `TrackMix` を identity に掛けて渡す。
- 複合クリップ・シーンの中: 中のレイヤーの消音・ソロは従来どおりその階層で解決し、鳴るレイヤーの `TrackMix` を外側の mix に `multiplied(by:)` で掛けて子へ渡す。したがって外 0.5 × 内 0.5 は 0.25、パンも左右別の乗算で合成される。
- クリップ単位の消音（`isMuted`）・無効化（`isDisabled`）は従来どおり絶対的に除外する。

### 既定時無変化の担保

トラック設定が無いプロジェクトでは、各クリップの `trackL` / `trackR` は次の連鎖で 1.0 ちょうどになる。

1. `audibleClipsWithTrackMix` は `TrackMixGains.identity.multiplied(by: TrackMix.of(tr))` から始める。既定の `TrackMix.of` は gain 1・pan 0。
2. `stereoGains` は `Float(1) * AudioPan.gains(0)`。`AudioPan.gains`（`AudioDSP.swift`）は `√2·cos(θ)` / `√2·sin(θ)`（θ = (pan+1)·π/4）を `Double` で計算してから `Float` にする。pan 0 では θ = π/4 で、`Double` 上の値は 1.0 から 1e-16 程度ずれ得るが、`Float` に丸めると左右とも 1.0 ちょうどになる（`Float` の刻みは約 1.2e-7 で、ずれはそれより遥かに小さい）。`AudioPan` のコメントも「中央は左右とも 1」としている。`TrackMixerTests` では、`stereoGains` が `AudioPan.gains` と一致することを確認している。
3. `multiplied` は `1.0 * 1.0` を左右それぞれ掛けるだけなので 1.0 のまま。入れ子でも、既定のレイヤーばかりなら 1.0 × 1.0 × … = 1.0。

その上で、IEEE 754 では「x × 1.0」は x とビット単位で一致する（符号付きゼロ・非正規化数・無限大・NaN も保たれる）。したがって、最終段の `… * it.trackL` や `g * it.trackL`（= `g * 1.0 = g`）は結果を変えない。
計算順序も従来のままにしてある。速い道でない経路・フェード経路は従来の式の末尾に `* it.trackL` / `* it.trackR` を足しただけで、既存の乗算の順序・結合は変えていない。速い道は `g` を左右別の `gl` / `gr` に置き換えただけで、既定時は `gl = gr = g * 1.0 = g`。

この保証は、コードの読み取りと浮動小数の性質に基づく説明に加えて、`TrackMixerTests` で既定時の書き出し（CAF の PCM）の全サンプルが従来の設定なしと一致することを確認している。

### 解析キャッシュ（`Sources/MovieCutCore/RenderAssets.swift`）

`RenderAssets.mixKey` の内部構造体 `AudioTrack` に `volume` / `pan`（どちらも `Double?`）を足した。値は丸め後（`trackVolumeOrDefault` / `trackPanOrDefault`）で、既定のときは `nil` にする。Swift の自動合成 `Encodable` は `nil` のキーを出力しないので、設定が無いプロジェクトの指紋は従来と同じ文字列になり、既存の解析キャッシュは無効にならない。設定を変えたときだけ指紋が変わり、古い解析結果が残らない。`muted` / `solo` は既存の `audible` 経由で指紋に入っている。

## 未検証事項

正直に書くと、次は確認していない（または、この文書の作成時点で結果を持っていない）。

- 実機での聞き比べ: 未実施。トラック音量・パンを動かしたときの聞こえ方、既定時に従来の書き出しと耳で同じかどうかは、耳では確かめていない。上の「既定時無変化」は、テストでは全サンプル一致を確認しているが、耳で聴き比べた確認ではない。
- UI の見た目の目視確認: 未実施。シートのレイアウト、ダーク/ライトでの見え方、dB・L/C/R 表示の見え方は、アプリを起動して見ていない。
- テストの結果（報告時点）: `swift test --filter TrackMixerTests` は 27 件すべて成功。`swift test --filter MovieCutCoreTests` は 2710 件成功・失敗 0（9 件はスキップ）。`swift build` は成功。`swift test --filter MovieCutTests`（アプリ側）は 873 件成功・失敗 0。
- プレビュー再生: 書き出しのミックスは `AudioMixer.mixdownDetailed` 経由だが、プレビュー再生が同じ経路を通るかは、この文書では確認していない。
- 複合クリップ・シーンの中のレイヤーについて、UI からは外側のレイヤーしか操作できない（シートに並ぶのはプロジェクト直下のレイヤーだけ）。内側のレイヤーの `volume` / `pan` は保存形式・ミックスとしては効くが、操作するシートは無い。
