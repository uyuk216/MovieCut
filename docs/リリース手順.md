# リリース手順(配布版・自動アップデート)

配布版(`--edition public`)だけが [Sparkle 2](https://sparkle-project.org/) で自動アップデートします。個人版は Sparkle をリンクせず、アップデートの確認をしません。
アップデート情報(appcast.xml)は GitHub Releases に添付し、アプリは次の URL を見ます:
`https://github.com/uyuk216/MovieCut/releases/latest/download/appcast.xml`

ここは手動の手順です(Remixa の `RELEASING.md` と `release.yml` を元にしました)。Movie Cut は SwiftPM + `Scripts/make-app.sh` で作るので、Remixa の xcodebuild 用ワークフローはそのままは使えず、`.github/workflows` は作っていません。

## 初回だけ: EdDSA 鍵

1. Sparkle の配布物(`Sparkle-2.x.tar.xz`、<https://github.com/sparkle-project/Sparkle/releases>)を展開する。`bin/generate_keys` が入っている。
2. `./bin/generate_keys` を実行。**秘密鍵は自分の macOS キーチェーンに保存**され、公開鍵(Base64)が表示される。
3. 公開鍵を、ビルド時の環境変数 `MOVIECUT_SPARKLE_PUBLIC_KEY` に渡す(`SUPublicEDKey` に入る)。
   未設定だと `PLACEHOLDER_...` が入り、そのビルドはアップデートを確認しない(メニュー項目も出ない)。
4. 秘密鍵は絶対にリポジトリへ入れない。バックアップが要るなら `./bin/generate_keys -x 保存先` で書き出し、安全な場所に保管してから、書き出したファイルを消す。

## 1 リリース

1. `Scripts/make-app.sh` の `VERSION` を上げてコミット(Sparkle はバージョン番号の大小で新しさを判断する。`CFBundleVersion` も同じ値)。
2. 配布版を作る(鍵を渡す):
   ```sh
   MOVIECUT_SPARKLE_PUBLIC_KEY='(公開鍵)' Scripts/make-app.sh dmg --edition public
   ```
   `build/public/Movie Cut.app` と `build/public/MovieCut-<版>-arm64.dmg` ができる。個人情報の検査も通る。
3. アップデート用に zip(または dmg)に署名する。Sparkle の `bin/sign_update` は、キーチェーンの秘密鍵を使う:
   ```sh
   ditto -c -k --sequesterRsrc --keepParent "build/public/Movie Cut.app" build/public/MovieCut-<版>.zip
   /path/to/Sparkle/bin/sign_update build/public/MovieCut-<版>.zip
   ```
   出力の `sparkle:edSignature="…" length="…"` を次の appcast に使う。
   (複数版がある場合は、zip を 1 つのフォルダに集めて `bin/generate_appcast <フォルダ> --download-url-prefix https://github.com/uyuk216/MovieCut/releases/download/v<版>/` でも `appcast.xml` を作れる。)
4. `appcast.xml` の例(1 版だけの場合):
   ```xml
   <?xml version="1.0" encoding="utf-8"?>
   <rss version="2.0" xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle">
     <channel>
       <title>Movie Cut</title>
       <item>
         <title>Version 0.2.1</title>
         <pubDate>Sat, 07 Nov 2026 12:00:00 +0900</pubDate>
         <sparkle:version>0.2.1</sparkle:version>
         <sparkle:shortVersionString>0.2.1</sparkle:shortVersionString>
         <sparkle:minimumSystemVersion>14.0</sparkle:minimumSystemVersion>
         <enclosure url="https://github.com/uyuk216/MovieCut/releases/download/v0.2.1/MovieCut-0.2.1.zip"
                    sparkle:edSignature="(sign_update の出力)" length="(バイト数)" type="application/octet-stream"/>
       </item>
     </channel>
   </rss>
   ```
5. タグを付けて、GitHub Releases に zip と `appcast.xml` を添付する(リポジトリを作って自分で push したあと):
   ```sh
   git tag v0.2.1 && git push origin v0.2.1
   gh release create v0.2.1 build/public/MovieCut-0.2.1.zip build/public/MovieCut-0.2.1-arm64.dmg appcast.xml --title "Movie Cut v0.2.1" --generate-notes
   ```
   アプリが見る `releases/latest/download/appcast.xml` は「最新の Release に付いた appcast.xml」を指す。毎回 `appcast.xml` を添付すること。

## ワンコマンド

上の 1 リリースの手順を `Scripts/release.sh` がまとめて行う。

```sh
export MOVIECUT_SPARKLE_PUBLIC_KEY='(公開鍵)'
Scripts/release.sh --version 0.2.1            # 既定は --dry-run(コミット・タグ・push・gh release はしない)
Scripts/release.sh --version 0.2.1 --publish  # 署名・版上げコミット・タグ・push・gh release まで
```

- 作業ツリーがきれいでないと止まる。`--skip-tests` で `swift test` を省ける。
- dry-run はキーチェーンに触れないので署名せず、`build/public/appcast.xml` は署名なしの下書きになる。終了時に `VERSION` の書き換えを元に戻す。
- `--publish` には `gh auth login` 済みの gh、origin リモート、Sparkle の `sign_update`(`.build/artifacts` か環境変数 `SPARKLE_BIN`)が要る。
- リリースノートは前のタグ以降の `git log` から作る。

## 注意

- 署名は ad-hoc(`codesign -s -`)。Developer ID・公証はしていないので、初回起動は右クリック「開く」が要る場合がある。Sparkle の更新自体は EdDSA 署名で検証される。
- 公開鍵と秘密鍵が別の鍵ペアだと、アップデートの署名検証が失敗する。
- appcast の URL が 404 のときは、タグ名と enclosure の URL、`appcast.xml` を添付したかを確認する。
- やり直すときは、同じタグを再利用せず新しい版にする。
