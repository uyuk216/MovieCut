# メディアインテリジェンス検索(第 1 段: 文字起こし文による素材内検索)

Premiere Pro の「メディアインテリジェンス／素材の自然言語検索」の段階実装です。
第 1 段では、**すでに文字起こし済みの素材**について「話している内容の文」で
プロジェクト内の素材を横断検索し、一致した文の開始位置へジャンプできるようにしました。
映像の内容そのものを文章で探す検索(「キーボードを打つ手」のような映像内容の検索)は
第 2 段で、この文書の最後に設計の見通しを書いてあります。

## 使い方

1. 先に素材を文字起こしします。音のあるクリップを選んで、次のどれかを実行してください。
   - 出力 ▸ 音声から字幕を作る… / 音声から字幕を作る(Whisper)…
   - 出力 ▸ 文字起こしを書き出す… / 文字起こしを書き出す(Whisper)…
   - クリップ ▸ 文字起こしで編集…
   実行した文字起こしの結果は、検索用の保存庫に自動で登録されます
   (文字起こし自体の結果・字幕・書き出しファイルは従来どおりです)。
2. 出力 ▸ **素材の内容を検索…** を開き、探したい言葉を入れます。
   - 一致した文が「素材名 + 素材の中の時刻 + 文」で並びます。
   - 結果の「その位置へ移動」を押すと、その文を使っているクリップが選ばれ、
     再生ヘッドが文の開始位置へ動きます(シートは閉じます)。
   - タイムラインに無い素材、またはクリップが使う範囲の外の文は、
     「その位置へ移動」が押せない形で出ます(素材の中の時刻は表示されます)。
3. 文字起こしが無い素材は、シートの下部に「検索の対象外(文字起こしがありません)」
   として名前が並びます。**検索のために勝手に文字起こしを始めることはありません。**

検索の仕様:

- 検索語は空白で区切って複数入れられ、すべての語を含む文が一致します(部分一致)。
- 表記ゆれは吸収します: ひらがな⇔カタカナ(「きーぼーど」で「キーボード」に一致)、
  全角⇔半角(「10時」で「１０時」に一致)、英字の大文字・小文字、文末の句読点や空白の有無。
- 吸収しないもの: 長音の書き分け(「きーぼーど」と「きいぼうど」は別)、
  送り仮名や同義語の違い、漢字⇔かなの違い(「今日」と「きょう」は別)。
  ここは第 2 段の埋め込み照合で扱う領域です。

## 索引の設計

- 索引(`MediaSearch.Index`)は**保存しません**。検索シートを開くたびに、
  プロジェクトが参照する素材(`mediaPool` とクリップの `src` の和集合。動画・音声のみ)と
  保存庫の文字起こしから組み立てます。再構築できるものは保存しない、が既存の作法です。
- 索引の項目(`MediaSearch.Entry`)は `kind` を持ちます。第 1 段は `.transcript` のみですが、
  第 2 段で映像特徴の項目を同じ索引・同じヒット表示(素材 + 時刻)に足せます。
- ヒットの時刻は「素材の頭からの秒」です。タイムラインへの対応づけは
  `MediaSearch.timelineLocation` が行い、素材時刻とタイムライン時刻が 1 対 1 の
  クリップ(文字起こしの対象と同じ条件)で、使う範囲に文の開始位置を含むものだけを対象にします。

## 文字起こしの保存先(なぜプロジェクト保存に入れないか)

- 既存の作法では、文字起こし結果はプロジェクトファイルに保存されません
  (認識は都度実行し、結果は字幕・書き出し・テキスト編集へ流して終わりです)。
  プロジェクト形式(`Project` のキー)を増やさないため、第 1 段もこの作法に合わせました。
- 代わりに、検索の元になる文字起こしは再構築可能なキャッシュとして
  `Application Support/MovieCut/MediaTranscripts.json`(`DataLocations.transcriptCache`、
  配布版は配布版のフォルダ)に素材ファイルごとに保存します(`MediaTranscriptStore`)。
  - キーは解決済みの実パス。文の時刻は素材の頭からの秒に直して持ちます
    (クリップの使う範囲の頭から測った認識時刻に `offset` を足します)。
  - 部分的な範囲の文字起こしを何度かに分けて実行しても、文は重ねて蓄積されます(重複は除く)。
  - 素材ファイルが差し替わると、目印(サイズ・更新日時)が合わなくなり、
    その素材の記録は捨てられて「文字起こしなし」に戻ります
    (`MediaFingerprintCache` と同じ考え方です)。
  - このファイルが消えても実害はありません。もう一度文字起こしすれば戻ります。
- 登録の経路は 3 つだけです(上の「使い方」1 の操作)。話者分離・フィラー検出の
  認識結果は登録しません(どちらも文の一覧を確定させる操作ではないため。第 2 段で検討)。
- CLI(`moviecut-cli transcribe`)の認識結果も登録しません(CLI は保存庫を持たない作法のため)。

## 第 2 段への見通し(映像内容の検索)

- 映像特徴の抽出: 素材から一定間隔でフレームを取り、Vision の特徴プリント
  (`VNGenerateImageFeaturePrintRequest`)や物体・顔検出の結果を、
  索引の項目(`kind` を追加)として同じ `MediaSearch.Index` に足す想定です。
  テキスト埋め込みとの照合にはローカル埋め込みモデル(Core ML)の選定が前提で、
  棚卸し表の等価機能案どおり段階を分けます。
- 保存: 映像特徴も再構築可能なキャッシュに置く想定です(プロジェクト保存には入れない)。
  特徴プリントは素材の目印(サイズ・更新日時)と組にして、`MediaTranscriptStore` と
  同じ失効の仕組みを使えます。
- UI: 検索シートは既に「素材 + 時刻」のヒット表示とジャンプ導線を持っているので、
  第 2 段は検索の照合方法の追加が中心になります。文字起こしが無い素材が
  「対象外」に出る枠組みも、映像解析が無い素材の表示にそのまま使えます。

## 未検証事項

- 実素材での画面操作(メニューからシートを開く、結果を選んでジャンプする)は
  単体テスト(モデル経由のジャンプ・メニュー項目・索引と検索の Core テスト)までで、
  GUI の実操作確認はしていません。
- 長い素材・多数の素材での検索シートの表示速度は未計測です
  (索引の組み立ては保存庫の JSON 読み込み + 全文の単純な部分一致です)。
- 文字起こしの登録は、アプリの 3 経路(字幕生成・書き出し・文字起こしで編集)からのみです。
  それ以外の経路で作った字幕(台本からの自動生成など)は検索対象になりません。
- 複合クリップの中の素材は、索引の素材一覧(トップレベルのクリップ + `mediaPool`)に
  含まれないことがあります(既存の素材収集 `MediaFingerprintCollector` と同じ範囲)。
