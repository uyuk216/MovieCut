# プロキシワークフロー

大きな映像を編集するとプレビューが重くなるため、軽いコピー(プロキシ)でプレビューだけを滑らかにする仕組みです。プロキシはプレビュー専用で、**書き出しは常に元の素材(原本)を読みます**。

## 原則

- 書き出しは常に原本。プロキシの有無・関連付けは書き出しの結果に影響しません。
- プロキシはプレビューの読み先を変えるだけです。素材のパスや書類の中身(クリップ・効果など)は変わりません。
- 外部のプロキシ(関連付けたファイル)は、削除の対象にしません。消すのは、アプリが作った生成済みのプロキシだけです。
- 関連付けたファイルが消えていた場合は、生成済みのプロキシに戻ります(プレビューが壊れないように)。生成済みも無ければ原本を読みます。

## 使い方

### 1. 手動で作る

**出力 ▸ プロキシを作成** で、この書類の映像の素材ごとに 540p のプロキシを背景で作ります。作成中は編集をロックします(書き出しと同じ)。キャンセルできます。作成済みの素材は飛ばします。

### 2. 取り込み時に自動で作る

**表示 ▸ 取り込み時にプロキシを自動作成** をオンにすると、映像を取り込んだときに背景で作ります。

- 編集はロックしません。
- 表示の短い辺が 540 以下の映像は作りません(縮める意味がないため)。
- 失敗しても状態欄は騒がず、作れた件数だけを知らせます。
- 対象は「素材を追加」「ドロップ」で置いた映像です。PSD・SVG・MIDI・連番画像は対象外です。

### 3. プレビューで使う

**表示 ▸ プロキシで編集** をオンにすると、プレビューは作成済みのプロキシ(または関連付けたファイル)を読みます。オフなら原本を読みます。

### 4. 管理シート(プロキシを管理…)

**出力 ▸ プロキシを管理…** で開きます。素材ごとに次の状態を表示します。

| 状態 | 意味 |
|---|---|
| 外部プロキシを使用中 | 関連付けたファイルを読んでいる |
| 生成済み(サイズ) | アプリが作ったプロキシを読んでいる |
| 未作成 | プロキシが無い(原本を読む) |

素材の印として「複合クリップ内」「シーン内」を付けます(トップレベルの素材には付けません)。

- **作成**: 未作成の素材を 1 件だけ作る。
- **関連付ける… / 変更…**: 手元のファイルを選び、この素材のプレビュー用に関連付ける(書類に保存。Undo 1 回)。
- **解除**: 関連付けを外す(ファイルは消えない)。
- **削除**: 生成済みのプロキシを消す(素材・外部のファイルは消えない)。
- **すべて削除**: この書類の生成済みのプロキシをまとめて消す。
- シートの下部で「取り込み時にプロキシを自動作成」を切り替えられます。

## 設定と保存場所

| 項目 | 保存先・キー | 既定 | 備考 |
|---|---|---|---|
| プロキシで編集 | UserDefaults `previewProxyEnabled` | オフ | アプリ全体。プレビューだけに効く |
| 取り込み時に自動作成 | UserDefaults `proxyAutoCreateEnabled` | **オフ** | アプリ全体 |
| 生成したプロキシ(保存済みの書類) | **プロジェクトファイルの隣の `proxies/`**(パッケージ保存ならパッケージ直下の `proxies/`)。ファイル名は元のパス・更新日時・サイズの SHA-256 | — | プロジェクトの資産。フォルダごと移動・コピー・同期できる |
| 生成プロキシの記録 | 書類の `proxyAssets`(元のパス → `{file: "proxies/…mp4"(フォルダからの相対), sourceSize}`) | なし | 作ったときだけ書く。空なら従来と同じファイル |
| 生成したプロキシ(未保存の書類・従来) | `Application Support/MovieCut/Proxies`(同じ命名) | — | 暫定置き場。従来のキーでも引けるので、既存のプロキシはそのまま使える |
| 外部の関連付け | 書類(`.mcpjc` の `proxyLinks`、元のパス → 外部のパス) | なし | 設定したときだけ書く。空の書類は従来と同じファイル |

### 自動作成の既定をオフにした理由

- 重い変換を、利用者の操作なしに始めないため。
- 「プロキシで編集」がオフのあいだは作っても使われず、ディスクを食うだけになるため。

## プロジェクト内プロキシ(仕様01 M-06/M-07)

生成プロキシはキャッシュではなく**プロジェクトの資産**です。「プロジェクト+プロキシを同期し、原本は各マシンのローカルにリンクする」運用ができます。

- **置き場**: 保存済みの書類は、プロジェクトファイルのフォルダの `proxies/` に作ります(1 つのフォルダに複数の書類があっても、名前は素材のハッシュなので衝突しません)。
- **記録**: 作ったプロキシは書類の `proxyAssets` に相対パスで記録します。開き直しても、フォルダを移動・コピーしても、相対で引けます(「..」や絶対パスで外へ出る記録は無視)。
- **原本が別の場所でも**: 原本が手元に無い(別マシン)ときは記録を信じてプロキシを使います。原本が手元にあって、作ったときと大きさが違えば古いプロキシとして使いません(作り直し)。素材の再リンク(ハッシュ一致の一括再リンク含む)で素材のパスが変わると、`proxyAssets` と `proxyLinks` のキーも新しいパスへ付け替えます(プロキシのファイルは動かしません)。
- **未保存の書類**: 暫定でアプリ側(`Application Support/MovieCut/Proxies`)に作ります。**最初の保存・名前を付けて保存でフォルダが決まると、プロジェクトの `proxies/` へコピーして記録します**(元のアプリ側ファイルは消しません。ほかの書類が使っているかもしれないため)。コピーは書類の編集として扱われるので、そのあと保存してください。
- **既存の書類・既存のプロキシ**: 開いただけでは何も移さず、書類も汚しません。記録が無ければ従来のキーでアプリ側から引きます。管理シートの「アプリ側のプロキシを取り込む」で、いつでもプロジェクトへコピーできます。
- **パッケージ化(素材集約)**: パッケージとして保存するとき、**生成プロキシも `proxies/` に同梱**します(素材を同梱できたものだけ)。外部プロキシ(`proxyLinks`)は参照のままで、同梱しません。
- **解決の順**: 外部リンク(実在すれば)→ プロジェクト内の生成プロキシ → アプリ側の従来プロキシ → なし(原本)。
- **書き出し**は従来どおり常に原本です。
- 管理シートでは、各素材の生成プロキシの「プロジェクト内 / アプリ側」・サイズ・場所を表示し、削除できます(プロジェクト内のものは記録も外れます)。

## 注意

- プロキシは元の素材の更新日時やサイズで名前が決まります。素材を差し替えると古いプロキシは使われず、作り直しが必要です。
- `proxies/` の同じファイルを複数の書類が記録している場合、片方から削除するともう片方の記録は切れます(その書類は原本、またはアプリ側の従来プロキシに戻ります)。
- 外部の関連付けは、書類に記録したパスで参照します。ファイルを移動すると切れ、生成済みのプロキシに戻ります。

## 未検証事項

- 画面操作(シートの表示・ボタンの動き・メニューの見た目)の実機確認は、この変更の時点では未実施です。テストはモデルとメニューの仕様表を対象にしています。
- 取り込み時の自動作成で「大きい映像が実際に作られる」ことは、App テストでは確認していません(判定ロジックは Core テストで確認済み)。
