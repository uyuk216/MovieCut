# シーン／ネスト(W3-01、YMM4 監査 #7)設計メモ

- 実装日: 2026-11-19 / ブランチ: `feat/scenes-nesting`
- 対象: YMM4 のシーン機能(場面ごとに独立したタイムラインを持ち、シーンを素材として配置・再利用できる仕組み)

## 複合クリップとの関係(着手前の精査結果)

MovieCut には既に複合クリップ(`CompoundEditing` / `CompoundScope`)がある。両者は「入れ子」という点では同じだが、所有と参照の形が違うため、別機構として共存させるのが正しいと判断した。

| | 複合クリップ | シーン(今回) |
|---|---|---|
| 中身の置き場所 | クリップ自身が `Clip.tracks` として「値で」抱える | プロジェクト級の定義 `Project.scenes` に置く |
| 参照の形 | 所有はそのクリップ 1 つだけ。コピーすれば中身も複製 | クリップは `sceneId` で「参照」するだけ。複数箇所から参照でき、定義を直せば全参照先に反映 |
| 主な用途 | 選択したクリップをその場で 1 本にまとめる | 名前付きの場面(導入・本編・締め等)を素材として使い回す |
| 名前・一覧 | 無し(メモが表示名の代用) | 名前付きで一覧管理(作成・名前変更・複製・削除) |

土台は複合クリップのものを流用し、二重機構の乱立を避けた:

- 時刻の窓切り: `CompoundEditing.window`(offset 〜 offset+duration を切り、頭を 0 に詰める)
- 音声の平坦化: `CompoundEditing.audibleClips` の flatten を拡張し、シーケンスクリップも同じ列に平らにする(レイヤー消音・ソロ・クリップ消音・無効化の意味論は複合と完全同一)
- 描画: `Renderer` の入れ子描画(背景・人物の立ち絵を描かない子 Renderer、祖先スタックで循環防止、キャンバスいっぱい・変形なしのときは親へ直接描く速い道)を複合と共有
- 深さ上限: 8 段(`CompoundEditing.maxDepth`)を複合・シーン混在でも共有の予算とする
- 編集スコープ: `CompoundScope` と同じ view/embed 方式を `SceneScope` として用意し、アプリ側も複合と同じ作法(入る・出るは Undo に載せない、中の編集は通常の `edit` 経由で根へ戻る)

シーン固有の差分として足したのは「参照グラフの循環検出」と「削除ポリシー」だけである。

## データ形式(後方互換)

- `Project.scenes: [SceneDefinition]`(id / name / tracks)。**空のときはファイルに書かない**。シーンを使わない既存プロジェクトは、読み込み・保存・描画・書き出しが従来と完全一致する(テストでバイト一致を確認)。
- シーンクリップ: `Clip.type == "scene"` + `Clip.sceneId`(参照先の `SceneDefinition.id`)。`sceneId` が無いクリップには書かない。型が違って読めない値は従来どおり `extra` に保持して書き戻す。
- 型名が `SceneDefinition` なのは、SwiftUI の `Scene` プロトコルと同名だとアプリ側で曖昧になるため。ファイル形式のキー名は `scenes` / `sceneId` で影響なし。

## 尺と時刻の扱い

- シーンの尺 = 中身のクリップの終わりの最大(空なら 0)。
- シーンクリップの `duration` が表示尺、`offset` がシーン内時刻の窓の頭(複合クリップと同じ意味論)。
- シーン内時刻 = (絶対時刻 − クリップの start) + offset で描画・音声ミックスする。窓の外(シーン尺を超えた分、duration を超えた分)は、子側にその時刻のクリップが無いことで自然に切り取られる。
- 配置時の `duration` はその時点のシーン尺で固定する。後からシーンが伸びても既存クリップの尺は自動では変わらない(複合クリップと同じ)。

## 削除ポリシー

**参照されているシーンは削除できない。** メイン・他のシーン・複合クリップの中のどこか 1 箇所でも参照があれば、モデル層(`SceneEditing.delete`)が nil を返し、アプリ層は理由を状態欄に出す。参照クリップを先に削除するのが手順。参照が黙って壊れて「何も描かれないクリップ」が残る事態を防ぐための選択で、テストで担保している。

## 循環・深さの防止(堅牢性)

- 配置時: シーン参照グラフで「置くシーンから配置先シーンへ辿れる」場合は循環になるので拒否(自分自身への配置を含む)。入れ子の最長段数が上限 8 以上になるシーンも配置を拒否。
- 描画・音声: 祖先スタック(複合は clip id、シーンは `scene:<id>` の印)で循環を止め、深さ上限を超えた先は描かない・混ぜない。ファイルから読んだ循環・過深データでも無限ループしない(テストで担保)。
- 参照先が無いシーンクリップは黙って何も描かない(落ちない)。

## 書き出し

プレビューと書き出しは同じ `Renderer` / `AudioMixer` 経路を通るため、シーンの描画・音声も同一結果になる。音声は `audibleClips` の平坦化を共有するので、ミックスダウンのサンプル一致をテストで確認済み。アプリ側は書き出し前にシーンのスコープから出る(複合と同じ)が、編集中でも `rootProject` は常に完全な書類を返す。

## 編集導線(アプリ)

- メニュー「クリップ ▸ シーン一覧…」: 作成・名前変更・複製・削除(参照中は不可)・配置(再生ヘッド位置、選択レイヤー)・開く。
- 「シーンを開く」(シーンクリップ選択時) / 「シーンから出る」: 複合クリップと同じ画面遷移。シーンの中では複合スコープに入れない(スコープは 1 段だけ)。
- タイムラインのダブルクリックでシーンを開く操作は未実装(メニューと一覧シートから開ける)。

## 未達・留保

- シーンクリップのサムネイル表示は最低限(通常クリップと同じ枠)。専用の色・名前表示(シーン色・ラベル・左上の「シーン」札)は R2-3 で追加済み。
- 「選択クリップからシーンを作成」は R2-3 で実装済み(クリップ ▸ 選択からシーンを作成。選んだクリップを新しいシーンにまとめて置き換える)。
- シーン内での配置は一覧シートの「配置」から可能(編集中はそのシーンの中に置く。循環は検証で拒否)。
