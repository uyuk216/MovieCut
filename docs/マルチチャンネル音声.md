# マルチチャンネル音声（W5-3）

5.1ch 等のマルチチャンネル素材を、黙って壊さずステレオで扱うための現状・設計・保留事項。

## 現状確認（probe の結論）

前任の調査用 probe テスト 2 件（`MultichannelProbeTests` / `MultichannelProbe2Tests`、
保全コミット 030e3af）は **print のみで assert が無く、実行結果（ログ）もリポジトリに残っていない**。
そのため「probe の実行で何が観測されたか」は再現できない。probe が調べようとしていた前提は
テストコードと現行コードの読み合わせで確定でき、結論は次のとおり。本実装では probe を削除し、
同じ合成信号（チャンネルごとに違う DC 値／トーン）を使う回帰テスト
（`MultichannelAudioTests`）に assert 付きで書き換えた。

### 読み込み経路は 2 つあり、壊れ方が違う

1. **File 経路（`FilePCMSource`、WAV/MP3/M4A/CAF 等の音声ファイル）— 壊れていた（確定）**
   - 旧コードは `read()` で `ch[0]` と `ch[1]` だけを拾い、3ch 以上の残りを黙って捨てていた。
   - つまり 5.1ch WAV では **センター（セリフの主成分）・LFE・両サラウンドが無音化**し、
     L/R だけが鳴る。サンプルレート変換時もチャンネル数は素材のまま通すので同じ。
2. **Asset 経路（`AssetPCMSource`、動画の音声トラック／AVAudioFile で開けない mp4 音声）— 変換は AVFoundation 任せ**
   - 旧コード（現行も既定は同じ）は `AVAssetReaderTrackOutput` に 2ch を要求し、
     ダウンミックスは AVFoundation 側が行う。チャンネルの並び・レイアウトを知っているのは
     AVFoundation なので、レイアウト付きコンテナ（mp4 の AAC 5.1 等）ではこちらが正しい経路。
   - ただし **AVFoundation の 2ch 変換が BS.775 係数どおりかは未検証**
     （probe2 は「要求チャンネル数 2 / 6 / 指定なしでサンプルとレイアウトがどう出るか」を
     print で見る設計だったが、結果ログが無い）。Mac 検証時の確認項目に残す（下記）。

### その他の経路

- ミックス段（`AudioMixer.mixdown`）・トラックミキサー（W2-1）・書き出し（`Exporter`）・
  再生（`PlaybackController`）はすべて **48 kHz ステレオ前提**で、音は最終的に
  `AudioMixer.mixdown` のステレオ CAF に合流する。したがって直すべき場所は読み込み段だけ。
- `AudioRemap`（速度・逆再生）も `AudioMixer.openSource` 経由なので、読み込み段の修正で一緒に直る。
- 波形表示（`AudioWaveform`）は全チャンネル平均でモノラル化しており、表示用途としては壊れていない（対象外）。
- 無音検出・スペクトログラム・文字起こしの素材読み出しも `openSource` 経由のため、
  本修正でセンター成分が拾えるようになる（従来は L/R のみが対象だった）。

## 実装

### ダウンミックス（`MultichannelAudio.swift`、純粋ロジック）

- 係数は **ITU-R BS.775 の Lo/Ro ダウンミックス**：
  - `Lo = L + 0.7071*C + 0.7071*Ls (+ 0.7071*Lb)`
  - `Ro = R + 0.7071*C + 0.7071*Rs (+ 0.7071*Rb)`
  - 0.7071 = 1/√2（−3.01 dB）。センターとサラウンドをこの係数で左右へ配るのが標準的な Lo/Ro。
  - **LFE は含めない**（BS.775 の Lo/Ro の定義どおり。LFE は低域専用で、ステレオ再生系では
    帯域外のことが多く、混ぜると全体が濁るため）。
  - 追加の正規化（全体を下げる処理）はしない。複数クリップの合算と同じく、
    最終段で `AudioMixer` が −1〜1 にクリップする既存の作法に合わせる。
- チャンネルの役割は**位置による前提**（File 経路と、Asset 経路でレイアウトが取れないときのフォールバック。
  Asset 経路のチャンネル選択はレイアウト優先 → 下記 Phase A）：
  1ch モノラル（左右複製）／2ch L,R／3ch L,R,C／4ch L,R,Ls,Rs（クアッド）／
  5ch L,R,C,Ls,Rs／6ch L,R,C,LFE,Ls,Rs（5.1、WAV/ffmpeg の標準順）／
  7ch は 6ch＋後方センター／8ch L,R,C,LFE,Lb,Rb,Ls,Rs（7.1 の WAV 順。
  バックとサラウンドは左右が同じなので係数は区別しない）。
  9ch 以上は 8ch 分を 7.1 として扱い、残りは左右交互に 0.7071 で足す
  （役割不明のチャンネルを黙って捨てないための保険）。
- モノラル/ステレオは係数が恒等/複製になるので、**従来とビット同一**
  （`FilePCMSource` は 2ch 以下を従来の速い道のままにしてある）。
- **リサンプルの順序（2026-11-20 修正）**：レート違い＋3ch 以上では、素材チャンネル数のまま
  `AVAudioConverter` に通さず、**素材レートで先にダウンミックスしてからステレオでリサンプル**する。
  Mac 対象テストで、多チャンネル→多チャンネルの変換では変換後の 3ch 目以降が 0 になり
  最初の 2ch しか残らないことを数値で確定したため（24 kHz 5.1ch DC の実測 0.4200 / -0.3600 は
  ch0/ch1 だけの値と誤差 4×10⁻⁵ で一致し、無音混入・順序入れ替わり・インターリーブ補間では
  再現できない）。ダウンミックス（サンプルごとの線形結合）もリサンプル（チャンネルごとに
  同じ線形フィルタ）も線形なので、順序の入れ替えは数学的に等価で、係数・期待値は変わらない。
  同一レートの場合は従来どおり変換後にダウンミックスする（コンバータを通らない）。

### チャンネル選択（Premiere のチャンネルマッピングの最小版）

- クリップ単位の `Clip.channelMode`（`SourceChannelMode`）：
  - `downmix`（既定・未設定）: 上記のダウンミックス。
  - `firstPair`: 最初の 2 チャンネルだけ（従来の挙動。先頭にステレオペアがある素材用）。
  - `center`: センターだけを左右同相で出す（5.1 のセリフ抽出用）。
    センターの無い素材（クアッド等）では無音にせずダウンミックスに倒す。
- 保存形式：**既定のときはキーを書かない**（未使用プロジェクトは従来とバイト完全一致）。
  知らない値は `extra` に保持して書き戻す（`audioCategory` と同じ作法）。
  編集は `AudioFxEditing.setChannelMode`、UI はインスペクタ「音声」の
  「素材チャンネル」ピッカー（パン の下）。文言は `L10nTable` に日英で追加。
- Asset 経路でチャンネル選択を指定したときだけ、素材のチャンネル数のまま読んで
  自前で選択する（形式記述の ASBD からチャンネル数を取得）。

### Phase A（改善ラウンド5 キュー2）: Asset 経路のレイアウト対応

**判定（コードで確定）：位置前提と素材のレイアウト順のずれは実在した。**
- `AssetPCMSource` は `channelMode != .downmix` のとき素材のチャンネル数のまま読み、
  返るサンプルは素材のレイアウト順（AAC 5.1 = MPEG 5.1 D: **C L R Ls Rs LFE**。Mp4AAC51ExportTests で実測済み）。
  一方、旧コードは `stereoWeights(channelCount:mode:)` で係数を**位置**（WAV 順 L R C LFE Ls Rs）に割り当てていた。
- そのため AAC 5.1 では ch0（実体は C）を L、ch2（実体は R）を C と誤認していた。
  `.center` は R のトーンを両耳に出し、`.firstPair` は C と L を出す（本来は L と R）。`.downmix` 相当の
  係数（ch ごとの BS.775）も C/L/R の役割が入れ替わるので、もし自前経路を通ると誤る。
  既定（`.downmix`）は自前経路を通らず AVFoundation の 2ch 変換に任せるので、従来から正しかった。
- なお `Clip.channelMode = .downmix` を明示しても `channelModeOrDefault` が `.downmix` のままなので、
  既定経路と同じ（読み込み時も `.downmix` は nil に正規化される）。

**修正内容：**
- `MultichannelDownmix` に役割ベースの係数 `stereoWeights(roles:mode:)` を追加。モードの意味を「位置」ではなく
  「役割」で定義した：`.downmix` は役割ごとの BS.775、`.firstPair` は役割が L/R のチャンネルだけ（先頭 2ch ではない）、
  `.center` は役割が C のチャンネルだけ（C が無ければ `.downmix` に倒す）。1ch はどのモードでも (1,1)。
  既存の `stereoWeights(channelCount:mode:)` は `roles(channelCount:)` 経由の薄いラッパで、挙動不変（テストで固定）。
- AVFoundation 型に依存しない純粋ロジックとして `roles(forLayoutTag:)`（レイアウトタグ → 役割表）、
  `role(forChannelLabel:)` / `roles(forChannelLabels:)`（UseChannelDescriptions のラベル → 役割）を追加。
  タグは AAC_5_1 / MPEG_5_1_A〜D / MPEG_5_0_A〜D / MPEG_6_1_A / MPEG_7_1_A〜C / AAC_6_0 / AAC_6_1 / AAC_7_0 / AAC_7_1 /
  Quadraphonic / Stereo / MatrixStereo / Mono を扱う。MPEG 7.1 A/B の Lc/Rc 用に役割 `leftCenter` / `rightCenter` を追加
  （BS.775 の 0.7071 で左右へ）。タグの数値は手書きなので、実際の `kAudioChannelLayoutTag_*` と突き合わせるテストを置いた。
- `AssetPCMSource` は、チャンネル選択時に `CMAudioFormatDescriptionGetChannelLayout` でレイアウトを取得して役割を決め、
  `stereoWeights(roles:mode:)` を使う。**フォールバック条件**（従来の位置前提 `roles(channelCount:)` に戻す）：
  レイアウトが無い／タグが未知（UseChannelBitmap、DiscreteInOrder 等を含む）／ラベルに不明が混じる／役割表の長さが素材の
  チャンネル数と合わない。
- **File 経路（`FilePCMSource`）は触らない（判断）。** 主用途の WAV 系は位置前提（WAV 順）が正しく、
  `AVAudioFile.processingFormat.channelLayout` は WAV では未設定（または出力側が付けた既定）になり得て、
  「確実に取れる」と言い切れない。誤認すると従来正しかった WAV の挙動を壊すリスクの方が大きいので、位置前提のまま据え置いた。

## 5.1 書き出し（改善ラウンド5 キュー2 Phase B）

統括判断（設計はユーザー側の統括決定。実装はこの方針のとおり）。**既定（ステレオ）選択時の出力は従来とバイト一致**で、
再生・プレビュー・ラウドネス測定は従来どおりステレオ。

### オプションの置き場
- Core: `ExportAudioChannels { stereo, surround51 }`（`Exporter.swift`。日本語ラベル `label`）。
  `Exporter.init(audioChannels:)`・`AudioExporter.export(audioChannels:)`・`ExportJob.run(audioChannels:)`・
  App の `ProjectModel.runExport(audioChannels:)` に、すべて既定 `.stereo` で追加。
- App: 保存パネルのアクセサリに「音声チャンネル」ポップアップ（ステレオ / 5.1 サラウンド、ID `export-audio-channels`、
  `ExportPanelOptions.selectedAudioChannels`）。文言は `L10nTable` に日英で追加。
- **保存はしない**：保存パネル内の一時選択のみで、プロジェクトファイルには入れない（ラウドネス・字幕埋め込みと同じ扱い）。

### ミックス（`AudioMixer.mixdownSurround51`）
- 中間形式は 48 kHz・**canonical 順 L R C LFE Ls Rs の 6ch** Float32（非インターリーブ、`MPEG_5_1_A` レイアウトつき。
  拡張子で .caf / .wav）。`mixdownDetailed`（ステレオ）とは**別関数**で、既存のシグネチャ・ステレオ本体は無変更。
  項目収集（`Item` の組み立て）は**共有化せず複製**した（ステレオ本体を壊さないことを優先）。
  将来 `mixdownDetailed` 側の収集を変えるときは、こちらも同期させる必要がある（要注意点）。
- 素材の読み方：`MultiPCMSource`（`PCMSource` を継承した別プロトコル。既存の準拠型は無変更）。
  - `FileMultiPCMSource`（WAV/CAF/M4A…）：素材のチャンネル数のまま読む。同一レートは変換なし。レート違いは
    **チャンネルごとにモノの `AVAudioConverter`** を通す（多チャンネルのままだと 3ch 目以降が落ちる実測があるため。
    リサンプルはチャンネルごとに同じ線形フィルタなので分解しても等価）。役割は位置前提（Phase A と同じ判断）。
  - `AssetPCMSource(forceNative: true)`：動画の音声を素材のチャンネル数・レイアウト順のまま読む。役割はトラックの
    AudioChannelLayout（取れなければ位置前提）。既定の 2ch 変換経路は無変更。
- クリップごとの寄与：
  - **エフェクト付き（内蔵チェーン/VST3/ノーマライズ/ノイズ除去）・速度/逆再生/音程のクリップ → ステレオ寄与**として L/R へ。
    理由：エフェクトの DSP はステレオ 2ch 前提で、5.1 に拡張しない（拡張すると状態・パラメータ・テストが全面的に増える）。
    `AudioRemap` の一時ファイルもステレオ前提なので同様。5.1 素材でもステレオにダウンミックスされて L/R に入る（制約）。
  - それ以外は `MultichannelDownmix.surround51Placements`（純粋関数、単体テストあり）で置く：
    - `.downmix`（既定）：3ch 以上は役割どおりのパススルー（L→L, R→R, C→C, LFE→LFE, Ls→Ls, Rs→Rs）。
      Lb/Rb → Ls/Rs へ 0.7071、Cs → Ls/Rs へ各 0.7071、Lc/Rc → L/R へ 0.7071（MPEG 7.1 A/B。指定外の補足）、
      8ch 超の余り → Ls/Rs へ 0.7071 交互。ステレオ素材は L/R、**モノラル素材は C（ゲイン 1.0）**。
    - `.firstPair`：役割ベースでステレオ化して L/R（モノラルは左右へ各 1.0）。
    - `.center`：センターの役割のチャンネルを C へ（1.0）。センターの役割が無い素材はダウンミックスして L/R へ。
  - ゲイン・フェード・音量キー・ダッキングは**全チャンネル共通の倍率**。パンは L/R にだけ掛ける
    （C/LFE/Ls/Rs には掛けない。モノラル素材は C に置かれるのでパンは効かない）。
  - トラックミキサー：L/R には従来どおり trackL/trackR、C/LFE/Ls/Rs には (trackL+trackR)/2。
  - 最終段はチャンネルごとに −1〜1 へクリップ。
- 中間形式を canonical 順にした理由：WAV/CAF の標準 5.1 順（`MPEG_5_1_A`）に一致し、WAV 書き出し・テストの照合・
  役割→位置の対応が最も単純になる。AAC に渡す直前にだけ AAC の並びへ入れ替える。

### 対応形式の実態
- **WAV**：`mixdownSurround51(to: *.wav)` が 6ch WAV（5.1）になる。これが本経路の WAV 対応。
  （`WavFileWriter` / `PngWavExporter` のステレオ WAV は対象外・無変更。UI の書き出し種類に WAV は無いので、アプリからは使わない。）
- **mp4（`Exporter`）**：6ch AAC・384 kbps。**書き出し設定のレイアウトは `AAC_5_1`（C L R Ls Rs LFE）**にした。
  指示では `MPEG_5_1_A` を第一候補としたが、AAC エンコーダが確実に受けるタグは `AAC_5_1` だと
  `Mp4AAC51ExportTests` が実測で使っている。この環境では実機検証できないため、AVFoundation の自動並べ替えに頼らず、
  `Surround51AAC.reordered` で**サンプルを AAC 5.1 の並びへ入れ替え、形式記述にも AAC_5_1 を付ける**方法を選んだ
  （並びとラベルの両方が一致するので、どちらの解釈でも結果が同じ）。読み出し側は中間ファイルを `MPEG_5_1_A` 指定で読む。
  読み戻しは出力のレイアウトタグから `roles(forLayoutTag:)` で役割→位置を解決する（テストは固定位置を前提にしない）。
- **m4a（`AudioExporter`）**：同じ 6ch AAC。`.m4a` の AVAssetWriter が 6ch を受けない環境では、`canAdd` の確認で
  ステレオに倒す（stderr に 1 行）。
- **ProRes（.mov）**：5.1 を選んでも**従来どおりステレオ**（stderr に 1 行）。無圧縮 6ch の .mov は必須範囲外で未検証のため。

### ラウドネス正規化
`LoudnessNormalization` は 2ch 前提（`guard channelCount == 2`）なので、**5.1 書き出しでは適用しない**
（`Exporter` / `AudioExporter` とも、stderr に「5.1 書き出しではラウドネス正規化は適用しません」を 1 行出す）。ステレオ時は無変更。
UI でラウドネスをオンにしたまま 5.1 を選んだ場合も黙って無視はせず、ポップアップのツールチップとこのログで知らせる。

### 残件・未検証（正直に）
- **この変更は Linux VM（Swift 無し）で書いたため、ビルドもテストも未実行**。Mac での初回ビルド・
  `Export51Tests` / 既存テスト（MultichannelAudioTests / Mp4AAC51ExportTests / Exporter 系）の通過確認が必要。
- 特に実機で確かめたい点：(1) AAC エンコーダが `AAC_5_1` + 並べ替えサンプルで 6ch を受けること、読み戻しが役割どおりか
  （`Export51Tests.testExporterSurround51WavToMp4SixChannelAAC` / `testAssetPathAAC51Roles…`）、
  (2) `.m4a` で 6ch AAC が書けるか（書けなければステレオに倒れる。テストは両方を許容）、
  (3) `AVAudioFile(forWriting:)` が `MPEG_5_1_A` レイアウト付き 6ch WAV/CAF を書けるか
  （書けなければレイアウトなしにフォールバックする実装）、
  (4) レート違い 5.1 の `FileMultiPCMSource`（モノ変換器の `.noDataNow` 運用）— 単体テストは未作成。
- プレビュー・再生・メーター・ラウドネス測定はステレオのまま。エフェクト付きクリップの 5.1 化は未対応（上記）。
- File 経路の役割は位置前提のまま（Phase A の判断を踏襲）。レイアウト付き `.m4a` の AAC 5.1 は並びがずれる可能性（未検証）。
- CLI（`moviecut-cli`）に 5.1 オプションは未追加（必須範囲外。`ExportJob.run(audioChannels:)` を渡せば対応できる）。

## 見送った範囲（理由つき）

- **5.1 シーケンス／プレビュー・メーターの 5.1 化**：再生・プレビュー・ラウドネス測定・メーターは
  ステレオ前提のまま（5.1 **書き出し**は Phase B で実装済み。下記）。Premiere の 5.1 シーケンス相当
  （編集中に 5.1 で聴く・5.1 メーター）が必要なら別タスクとして設計から行う。
- **任意のチャンネルマッピング（チャンネルごとの行き先・係数の自由編集）**：
  Premiere の「チャンネルマッピング」全機能。まずは壊れないダウンミックス＋代表的な
  選択 2 種（firstPair / center）まで。需要が出たら係数表をクリップに持たせる形で拡張できる。
- **レイアウト情報（チャンネルラベル）による自動判別**：**Asset 経路は Phase A で対応済み**
  （上記「Phase A」。チャンネル選択時にトラックの AudioChannelLayout から役割を取り、取れなければ位置前提）。
  **File 経路は位置前提のまま**（WAV 系は WAV 順が正しいため。レイアウト付きの AAC 5.1 を `.m4a` として
  AVAudioFile で開いた場合は並びが WAV 順でない可能性があり、その経路は未対応・未検証）。
  File 経路をレイアウト対応にする場合も `MultichannelDownmix.roles(forLayoutTag:)` を使えばよい。
- **LFE の任意ミックス（量の調整）**：BS.775 どおり含めないで固定。必要なら係数追加で対応可能。
- **波形・ラウドネス等の表示系のチャンネル別表示**：対象外（現状でも壊れてはいない）。
