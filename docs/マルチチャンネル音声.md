# マルチチャンネル音声（W5-3）

5.1ch 等のマルチチャンネル素材を、黙って壊さずステレオで扱うための現状・設計・保留事項。

## 現状確認（probe の結論）

前任の調査用 probe テスト 2 件（`MultichannelProbeTests` / `MultichannelProbe2Tests`、
保全コミット 030e3af）は **print のみで assert が無く、実行結果（ログ）もリポジトリに残っていない**。
そのため「probe の実行で何が観測されたか」は再現できない。probe が調べようとしていた前提は
テストコードと現行コードの読み合わせで確定でき、結論は次のとおり。本実装では probe を削除し、
同じ合成信号（チャンネルごとに違う DC 値／トーン）を使う回帰テスト
（`MultichannelAudioTests`）に assert 付きで書き換えた。

### 読み込み経路は 2 つあり、壊れ方が違う

1. **File 経路（`FilePCMSource`、WAV/MP3/M4A/CAF 等の音声ファイル）— 壊れていた（確定）**
   - 旧コードは `read()` で `ch[0]` と `ch[1]` だけを拾い、3ch 以上の残りを黙って捨てていた。
   - つまり 5.1ch WAV では **センター（セリフの主成分）・LFE・両サラウンドが無音化**し、
     L/R だけが鳴る。サンプルレート変換時もチャンネル数は素材のまま通すので同じ。
2. **Asset 経路（`AssetPCMSource`、動画の音声トラック／AVAudioFile で開けない mp4 音声）— 変換は AVFoundation 任せ**
   - 旧コード（現行も既定は同じ）は `AVAssetReaderTrackOutput` に 2ch を要求し、
     ダウンミックスは AVFoundation 側が行う。チャンネルの並び・レイアウトを知っているのは
     AVFoundation なので、レイアウト付きコンテナ（mp4 の AAC 5.1 等）ではこちらが正しい経路。
   - ただし **AVFoundation の 2ch 変換が BS.775 係数どおりかは未検証**
     （probe2 は「要求チャンネル数 2 / 6 / 指定なしでサンプルとレイアウトがどう出るか」を
     print で見る設計だったが、結果ログが無い）。Mac 検証時の確認項目に残す（下記）。

### その他の経路

- ミックス段（`AudioMixer.mixdown`）・トラックミキサー（W2-1）・書き出し（`Exporter`）・
  再生（`PlaybackController`）はすべて **48 kHz ステレオ前提**で、音は最終的に
  `AudioMixer.mixdown` のステレオ CAF に合流する。したがって直すべき場所は読み込み段だけ。
- `AudioRemap`（速度・逆再生）も `AudioMixer.openSource` 経由なので、読み込み段の修正で一緒に直る。
- 波形表示（`AudioWaveform`）は全チャンネル平均でモノラル化しており、表示用途としては壊れていない（対象外）。
- 無音検出・スペクトログラム・文字起こしの素材読み出しも `openSource` 経由のため、
  本修正でセンター成分が拾えるようになる（従来は L/R のみが対象だった）。

## 実装

### ダウンミックス（`MultichannelAudio.swift`、純粋ロジック）

- 係数は **ITU-R BS.775 の Lo/Ro ダウンミックス**：
  - `Lo = L + 0.7071*C + 0.7071*Ls (+ 0.7071*Lb)`
  - `Ro = R + 0.7071*C + 0.7071*Rs (+ 0.7071*Rb)`
  - 0.7071 = 1/√2（−3.01 dB）。センターとサラウンドをこの係数で左右へ配るのが標準的な Lo/Ro。
  - **LFE は含めない**（BS.775 の Lo/Ro の定義どおり。LFE は低域専用で、ステレオ再生系では
    帯域外のことが多く、混ぜると全体が濁るため）。
  - 追加の正規化（全体を下げる処理）はしない。複数クリップの合算と同じく、
    最終段で `AudioMixer` が −1〜1 にクリップする既存の作法に合わせる。
- チャンネルの役割は**位置による前提**（レイアウト情報は使わない）：
  1ch モノラル（左右複製）／2ch L,R／3ch L,R,C／4ch L,R,Ls,Rs（クアッド）／
  5ch L,R,C,Ls,Rs／6ch L,R,C,LFE,Ls,Rs（5.1、WAV/ffmpeg の標準順）／
  7ch は 6ch＋後方センター／8ch L,R,C,LFE,Lb,Rb,Ls,Rs（7.1 の WAV 順。
  バックとサラウンドは左右が同じなので係数は区別しない）。
  9ch 以上は 8ch 分を 7.1 として扱い、残りは左右交互に 0.7071 で足す
  （役割不明のチャンネルを黙って捨てないための保険）。
- モノラル/ステレオは係数が恒等/複製になるので、**従来とビット同一**
  （`FilePCMSource` は 2ch 以下を従来の速い道のままにしてある）。
- **リサンプルの順序（2026-11-20 修正）**：レート違い＋3ch 以上では、素材チャンネル数のまま
  `AVAudioConverter` に通さず、**素材レートで先にダウンミックスしてからステレオでリサンプル**する。
  Mac 対象テストで、多チャンネル→多チャンネルの変換では変換後の 3ch 目以降が 0 になり
  最初の 2ch しか残らないことを数値で確定したため（24 kHz 5.1ch DC の実測 0.4200 / -0.3600 は
  ch0/ch1 だけの値と誤差 4×10⁻⁵ で一致し、無音混入・順序入れ替わり・インターリーブ補間では
  再現できない）。ダウンミックス（サンプルごとの線形結合）もリサンプル（チャンネルごとに
  同じ線形フィルタ）も線形なので、順序の入れ替えは数学的に等価で、係数・期待値は変わらない。
  同一レートの場合は従来どおり変換後にダウンミックスする（コンバータを通らない）。

### チャンネル選択（Premiere のチャンネルマッピングの最小版）

- クリップ単位の `Clip.channelMode`（`SourceChannelMode`）：
  - `downmix`（既定・未設定）: 上記のダウンミックス。
  - `firstPair`: 最初の 2 チャンネルだけ（従来の挙動。先頭にステレオペアがある素材用）。
  - `center`: センターだけを左右同相で出す（5.1 のセリフ抽出用）。
    センターの無い素材（クアッド等）では無音にせずダウンミックスに倒す。
- 保存形式：**既定のときはキーを書かない**（未使用プロジェクトは従来とバイト完全一致）。
  知らない値は `extra` に保持して書き戻す（`audioCategory` と同じ作法）。
  編集は `AudioFxEditing.setChannelMode`、UI はインスペクタ「音声」の
  「素材チャンネル」ピッカー（パン の下）。文言は `L10nTable` に日英で追加。
- Asset 経路でチャンネル選択を指定したときだけ、素材のチャンネル数のまま読んで
  自前で選択する（形式記述の ASBD からチャンネル数を取得）。
  この場合の並び前提も WAV 順になる点に注意（下記の保留事項）。

## 見送った範囲（理由つき）

- **5.1 シーケンス／5.1 書き出し**：ミックス・プレビュー・書き出し・メーターの全段が
  ステレオ前提の設計で、載せるには出力フォーマット全体の作り替えが要る。本タスクの範囲外。
  Premiere の 5.1 シーケンス相当が必要なら別タスクとして設計から行う。
- **任意のチャンネルマッピング（チャンネルごとの行き先・係数の自由編集）**：
  Premiere の「チャンネルマッピング」全機能。まずは壊れないダウンミックス＋代表的な
  選択 2 種（firstPair / center）まで。需要が出たら係数表をクリップに持たせる形で拡張できる。
- **レイアウト情報（チャンネルラベル）による自動判別**：WAV 以外（AAC 等）では
  チャンネル順がレイアウト依存になり得る。AVFoundation のレイアウト取得は
  `AudioChannelLayout` のポインタ操作が必要で、Linux 環境ではコンパイル確認ができないため
  リスクが高い。File 経路は WAV 系が主用途なので位置前提で割り切り、レイアウト付き
  コンテナの本命（動画）は Asset 経路の AVFoundation 変換に任せる構成にした。
  将来レイアウト対応する場合は `MultichannelDownmix.roles` を差し替えるだけで済む形にしてある。
- **LFE の任意ミックス（量の調整）**：BS.775 どおり含めないで固定。必要なら係数追加で対応可能。
- **波形・ラウドネス等の表示系のチャンネル別表示**：対象外（現状でも壊れてはいない）。

## 未確認事項（Mac 検証で見てほしい点）

- probe の実行ログが残っていないため、本実装のテストは「コードから確定する前提」を
  assert 化したもの。実機での `MultichannelAudioTests`（11 件）の通過が初回検証になる。
  → 2026-11-20 の初回検証で同一レート等の 10 件は通過し、リサンプル経由の 1 件だけが
  上記のとおり失敗したため、同日中に「ダウンミックス先行」へ修正した（Mac での再検証待ち）。
- Asset 経路：mp4 の 5.1ch AAC で、AVFoundation の 2ch 変換にセンター/サラウンドが
  含まれるか（probe2 が見ようとしていた点）。含まれない場合は Asset 経路も
  素材チャンネル数で読んで自前ダウンミックスへ切り替える必要がある
  （その際はレイアウト順の問題が残るので、実ファイルのレイアウト確認とセットで）。
- Asset 経路でチャンネル選択を指定したとき、ASBD から取得したチャンネル数で
  `AVAssetReader` が実際にそのチャンネル数のサンプルを返すか。
- 7.1ch 実素材（WAV 順でないもの）での役割の一致。
