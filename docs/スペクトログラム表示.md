# スペクトログラム表示(音声スペクトル表示)

Premiere Pro の「スペクトル表示」/ Adobe Audition のスペクトログラム相当として、
音声の周波数成分を時間 × 周波数で表示する機能の記録。棚卸しの残り候補
「スペクトル表示(スペクトログラム)」への対応。

## 使い方

- 音のあるクリップ(音声・ボイス・動画)をタイムラインで選んでから、表示 ▸ スコープ… を開く。
  従来の映像スコープ(ヒストグラム・波形・ベクトルスコープ・RGB パレード)の下に、
  選択中のクリップのスペクトログラムが並ぶ(シート内はスクロール)。
- 読み方: 横が時間(左がクリップの頭)、縦が周波数(対数、下が低域 20 Hz・上が 24 kHz)、
  色が強さ(黒 → 紫 → 赤紫 → 橙 → 黄 → 白の順に強い)。声のフォルマントの動き、
  ノイズの帯域、サイン波のような単音成分の有無などが目で分かる。
- 下に「いちばん強い周波数」(全体で最も強い成分、放物線補間で bin 間隔より細かく読んだ値)と
  「解析した長さ」が出る。長いクリップで先頭だけを解析したときは、その旨をオレンジで知らせる。
- 何も選んでいない・音の無いクリップを選んでいるときは、案内文が出る(計算はしない)。
- 「更新」で映像スコープと一緒に取り直す。表示専用で、書き出し・音そのものには影響しない。

## 実装

- Core(純粋な計算、画面なし): `Sources/MovieCutCore/Spectrogram.swift`
  - `Spectrogram.analyze(mono:sampleRate:config:)` — サンプル列からの STFT(純粋関数・決定的)。
  - `Spectrogram.analyze(clip:config:)` — クリップの素材範囲をミキサーと同じ経路
    (`AudioMixer.openSource`、48 kHz ステレオ → 左右平均でモノラル)で読みながら解析する。
  - `SpectrogramResult` — 線形 bin の強さ(0〜1)を保持。ピーク bin / ピーク周波数(放物線補間)/
    支配周波数、表示用対数バンドへの最大プーリング(`displayBands`)、色階調(`color(forIntensity:)`)。
  - `SpectrogramCache` — 波形の `WaveformCache` と同じ作法のメモリキャッシュ
    (`CacheBudgetManager` 配下で LRU 破棄、ディスクには書かない)。
- アプリ: `Sources/MovieCut/ScopeSheet.swift` が、シートを開いたときと「更新」で
  選択中クリップのスペクトログラムをバックグラウンドで計算し、対数バンド 96 段で描く。
  プロジェクトの保存形式には一切手を入れていない(解析結果はキャッシュのみ。
  `SpectrogramAppTests.testProjectEncodingHasNoSpectrogramData` で担保)。

### 計算の詳細

- STFT: FFT 2048 点、周期 Hann 窓、ホップは既定で FFT 長 / 4(75% 重ね)。
  実数 FFT は Accelerate(vDSP)で、`SpectrumAnalyzer` と同じ正規化
  (振幅 1 の正弦波が bin 中心で 1 になる)を使う。
- 強さは dBFS を 0〜1 へ線形に写す(0 dBFS = 1、−80 dB 以下 = 0。範囲は設定
  `dynamicRangeDb`、既定 80)。時間方向の平滑化はしない
  (ビジュアライザ用の `SpectrumAnalyzer` はアタック/ディケイ平滑化つきで、
  測定用途のこちらとは値の意味が違うため共用していない)。
- ピーク周波数はピーク bin の前後の値で放物線補間する(0〜1 の値は dB の線形写像なので
  そのまま補間に使える)。bin 間隔は 48 kHz / 2048 ≒ 23.4 Hz で、補間により
  その半分以下の誤差で読める(単体テストで ±12 Hz 以内を確認)。

### 既存部品との関係(再利用したもの・しなかったもの)

- 再利用: クリップの読み込み経路(`AudioMixer.openSource`、`SilenceDetector` と同じ)、
  キャッシュの作法(`CacheBudgetManager` + `WaveformCache` の形)、対象判定
  (`Clip.supportsAudioFx`。フリーズフレームは無音のため対象外)。
- 非再利用: `SpectrumAnalyzer`(ビジュアライザ用)は対数バンド化と平滑化まで含む描画専用の値で、
  ピーク周波数を読みたい本機能とは形が違う。`SpectralDenoise` の STFT はノイズ除去専用の
  内部型で公開されていない。どちらも無変更で、窓・FFT・正規化の作法だけ合わせた。
- 既存の波形表示(`AudioWaveform`)と映像スコープ類(`VideoScope` / `VectorScope` /
  `RGBParade`)は無変更。

## 計算の割り切り(長尺で固まらない設計)

- 解析する長さは素材の先頭 60 秒まで(`SpectrogramConfig.maxDuration`、範囲 1〜600 秒)。
  超える分は読まず、結果の `truncated` とシートの注意書きで知らせる。
- 時間方向の列数は最大 480(`maxColumns`)。短い素材はホップ 512(FFT 長 / 4)だが、
  列数が上限を超える素材ではホップを広げて列数を上限以下に抑える
  (例: 30 秒・48 kHz ならホップ ≒ 14,500 で 100 列を指定すれば 100 列)。
  そのため時間分解能は長い素材ほど粗くなる。周波数分解能(FFT 2048)は変わらない。
- 読み込みは 16,384 フレームずつのストリーミングで、保持するモノラル列も
  上限 60 秒分(48 kHz で 288 万サンプル ≒ 11 MB)まで。結果の保持も
  最大で 480 列 × 1024 bin × 4 バイト ≒ 2 MB で、キャッシュはメモリ予算の配下にある。
- 計算はシート側でバックグラウンド(`Task.detached`)に逃がすので、計算中も画面は固まらない。

## 対象と解釈の注意

- 速度・逆再生・速度ランプのあるクリップも対象だが、解析は素材の時間軸
  (クリップの `offset` から素材の長さ分)で行う。タイムライン上で速度を変えた後の
  聞こえ方(ピッチが上下した状態)そのものではない。
- 音量・パン・音声エフェクト(EQ 等)は反映しない。素材そのままの周波数成分を見る表示。
- 複合クリップ・シーンクリップは対象外(中身が素材ファイルではないため)。
  プロジェクト全体のミックスのスペクトログラムは未対応(ラウドネス測定のような全体表示は今後の課題)。

## テスト

- `Tests/MovieCutCoreTests/SpectrogramTests.swift`(21 件):
  単一周波数の正弦波(110 / 440 / 1000 / 4000 / 8000 Hz)でピーク周波数と支配周波数が合うこと、
  周波数の異なる 2 音(連続する切替と同時の混合)、無音でピークが無いこと、
  Hann 窓の性質(両端 0・中央 1・合計 n/2・対称)、ホップと列数の決まり方、
  長尺での列数上限とホップ拡大、尺の打ち切りと `truncated`、設定の丸め、
  bin と周波数の往復、表示バンドの対数等分とピーク位置、色階調の端点と明るさの単調性、
  空・不正サンプルレート・NaN/Inf を含む入力の安全な扱い、FFT より短い入力、
  クリップ経路(トーン WAV)とキャッシュ。
- `Tests/MovieCutTests/SpectrogramAppTests.swift`(4 件):
  選択中クリップの対象判定、新規文言の英訳、共有キャッシュ経由の実解析、
  プロジェクト保存にスペクトログラムが混ざらないこと。
