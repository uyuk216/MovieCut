# カラーマネジメント（入力色空間の変換）

映像クリップごとに「撮影時の色空間」を選ぶと、描画の頭で作業空間（Rec.709）へ変換してから、従来のエフェクト・LUT・色補正に入る。

## 使い方
- 映像クリップのインスペクタ ▸ 配置の「見た目」付近 ▸「入力色空間」。
- 選択肢: Rec.709（標準・既定）／S-Log3（S-Gamut3.Cine）／V-Log（V-Gamut）／HLG（Rec.2020）／Rec.2020（ガンマ）。
- プロジェクト全体の一括設定は未対応（クリップ単位のみ）。

## 仕組み
- 型: `InputColorSpace`（`Sources/MovieCutCore/ColorManagement.swift`）。数式は `ColorManagement` の純粋関数。
- 流れ: 符号化値 →（逆伝達関数）→ 線形 →（原色から求めた 3x3 行列）→ Rec.709 線形 →（BT.709 OETF）→ 符号化値。
- 33^3 の 3D LUT に焼き込み、既存の `.cube` LUT と同じ `CIColorCubeWithColorSpace` で適用する（`EffectPipeline` の先頭に `.colorSpace` として置く。他のエフェクトより必ず先）。
- 色域の行列は原色の xy 色度から計算する（S-Gamut3.Cine／V-Gamut／Rec.2020 → Rec.709、どれも D65 なので色順応なし）。公開値との一致をテストで確認。
- 保存: クリップの `inputColorSpace`（文字列 `slog3` / `vlog` / `hlg` / `rec2020`）。Rec.709 は書かない。フィールドの無い旧プロジェクトは Rec.709 として従来どおり開く。知らない値は捨てずにそのまま書き戻す。

## 割り切り（到達範囲）
- HDR 書き出しは範囲外。出力は従来どおり SDR（Rec.709 / sRGB 系）のみ。
- 作業空間は Rec.709 固定。広色域・Log のまま編集・書き出しはしない。
- HLG の OOTF（システムガンマ）は簡易版。基準白（信号 0.75）を SDR の白に合わせる定数倍だけで、ピーク輝度に応じたガンマ補正はしない。
- 色域外の値は Rec.709 の 0〜1 に丸める（ガマットマッピングはしない）。
- 33^3 の補間なので、Log の暗部ではごくわずかな補間誤差が出る。
- Rec.709 の動画は「符号化値のまま」扱う従来の挙動を変えない（Rec.709 のクリップは1画素も変わらない）。
- 同梱の変換は代表的な 5 種のみ（ACES・Canon Log・LogC などは未対応。`.cube` LUT を使う）。
