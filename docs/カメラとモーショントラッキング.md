# カメラとモーショントラッキング（W3-02 / W3-03）

YMM4 監査 #54（カメラ系）と #53（モーショントラッキング）の実装メモ。方式・操作・限界をまとめる。

## カメラ（#54）

- 保存先: プロジェクトの任意項目 `camera`（`CameraSettings`）。未設定・既定値のときはファイルに書かず、描画も従来経路のまま（画素単位で完全一致）。
- パラメータ:
  - 位置 X/Y: カメラ中心（画面中央に映る点。キャンバスに対する割合）
  - 注目点 X/Y: 回り込み・拡大の軸
  - 回り込み: 注目点を軸にした回転（度、画面上で時計回りが正）
  - 視野角: 視野角（度）。拡大率 = tan(30°) / tan(視野角/2)。既定 60° = 等倍
- 変換: 相似変換 `p' = C + R(θ)·z·(p − L) + z·(L − P)`（C = 画面中央、P = カメラ位置、L = 注目点、z = 拡大率）を、`Renderer.render` の最終合成段で 1 回だけ適用する。背景の塗りは変換の外。プレビューと書き出しは同じ `render` を通るため結果は一致する。複合クリップの中身（`drawFrame` 直接呼び出し）にはかからない。
- 複合クリップとの併用（重要・バッチO統合ブロッカー修正）: フレーム経路の複合クリップは `compoundRenderer` がプロジェクト全体をコピーして子の `renderImage` を呼ぶため、コピーが `camera` を含んでいると子側でもカメラがもう 1 回かかり、しかも子時刻（t − start + offset）でキーフレームが評価されていた（高速経路では二重適用が起きないため、同じ複合でも経路によって絵が変わっていた。実測: 200×100・左赤/右青・パン x=0.25 で、正解の境界 150 がフレーム経路では画面外へ飛んだ）。修正として `compoundRenderer` で子プロジェクトの `camera` を落とす（`sub.camera = nil`、`drawsBackground = false` と同じ扱い）。**作法: 子 Renderer 用プロジェクトでは camera を落とす。カメラは最上位の親の最終段でのみ 1 回適用する。**
  - **再統合担当への申し送り**: 本家統合済みのシーン経路（`sceneRenderer`、本ブランチの base には未収録）も、子プロジェクトをコピーして子の `renderImage` を呼ぶ構造なら同じ問題を持つ。再統合の際に `sceneRenderer` 側にも `sub.camera = nil`（子プロジェクトの camera を落とす）と同じ修正を入れること。回帰テストは `CameraCompoundTests`（高速経路 scale=1.0 とフレーム経路 scale=0.999 の色割り当て一致＋単独適用の正解＝境界位置の一致、キーフレームは親時刻で 1 回だけ評価）を参照。
- キーフレーム: 既存の `Keyframe` を再利用し、`camera.keyframes` に項目名（`x` `y` `targetX` `targetY` `orbit` `fov`）→ キー列で持つ。時刻はプロジェクト時刻（クリップのキーと違いクリップ頭基準ではない）。補間・イージングは `Animation.interpolate` と同じ。
- UI: プロパティ欄の「カメラ」節（クリップ未選択時／クリップ選択時の末尾）。数値入力＋◇（キーの付け外し）＋前後のキーへの移動。リセットボタンで未設定に戻る。

## モーショントラッキング（#53）

既存の `MotionTrack`（中央固定の矩形を追い、文字・図形・画像の x・y キーを作る簡易版）はそのまま残し、拡張層 `ObjectTracking` を追加した。

- 追跡: Vision `VNTrackObjectRequest`（既存 `VisionRectTracker` を共用）。10 回/秒でサンプル。開始矩形は呼び出し側が決める（ぼかし範囲クリップは自身の現在の矩形、それ以外は従来どおり中央 0.3 の正方形）。
- 結果の保存: `ObjectTrack`（元クリップ ID・開始矩形・サンプル列）を追従クリップの任意項目 `tracking` に保存する。適用は従来方式と互換なキーフレームへの焼き込み。
- 追従の適用先:
  - 変形クリップ（画像・動画・文字・図形・立ち絵・複合）: x・y（開始時点の対象との位置関係を保持）＋ scale（面積比の平方根。変化が小さいときは scale キーを作らない）
  - ぼかし範囲クリップ: x・y・w・h で矩形そのものに追従
- 顔ぼかしとの接続: 顔ぼかしエフェクト（W2-08）の `track` は顔検出専用の追従（`FaceTrack`）で、任意対象には使えない。任意対象のぼかし追従は「この映像の対象をぼかしで追従」（プロパティ欄）で、追跡結果からぼかし範囲クリップを新規作成して接続する。
- 実行: 非同期（裏スレッドでコマを 1 枚ずつ処理）。プロパティ欄に進捗バーと中止ボタンを出す。キャンセル時は部分結果を適用しない。見失った区間は直前の位置・大きさを保持し、平滑化は `AutoReframe.smooth`（時定数 0.15 秒）。

## 限界・未達

- 開始矩形のプレビュー上でのドラッグ指定 UI は無い（中央固定、またはぼかし範囲クリップ自身の矩形が開始矩形になる）。
- 追跡精度は Vision の物体追跡に依存する。速い動き・遮蔽・似た模様では外れることがある。テストは合成画像での疎通確認までで、実写での精度検証はしていない。
- 大きさの追従は面積比の平方根（等方スケール）のみ。対象の回転・傾きには追従しない。
- カメラは相似変換（平行移動・回転・一様拡大）のみ。注目点と位置の差による疑似パース（台形変形）は無い。
