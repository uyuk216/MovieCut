# ベベル系エフェクトと放射ブラー（棚卸し残り候補）

Premiere の「Bevel Alpha」「Bevel & Emboss」「Radial Blur」に相当する見た目の機能を、
汎用エフェクトとして追加した（`EffectKind.bevelAlpha` / `bevelEmboss` / `radialBlur`）。
基盤は Core の `Bevel`（ベベル共通）と `RadialBlur`。いずれも既存のキーフレーム機構
（`fx.<番号>.<引数>`）に乗り、インスペクタ・メニューへの露出は `EffectKind.allCases` 経由で自動。

## 引数

### ベベル（アルファ） `bevelAlpha` — アルファ形状の縁に斜面を付ける

| キー | 範囲 | 既定 | 意味 |
|---|---|---|---|
| size | 0〜40 px | 0 | 斜面の厚み（光方向への読みずらし量）。0 = 何もしない |
| angle | −180〜180° | 135 | 光源がある向き（右が 0°、反時計回りが正）。135° は左上からの光 |
| softness | 0〜40 px | 4 | 斜面のなだらかさ（場のガウスぼかしの σ） |
| highlight | 0〜1 | 0.7 | ハイライト（光に面した側を白く）の強さ |
| shadow | 0〜1 | 0.7 | シャドウ（反対側を黒く）の強さ |

### ベベル＆エンボス `bevelEmboss` — 不透明な映像にも使える浮き出し

| キー | 範囲 | 既定 | 意味 |
|---|---|---|---|
| depth | 0〜40 px | 0 | 浮き出しの深さ（読みずらし量）。0 = 何もしない |
| angle | −180〜180° | 135 | 光源がある向き（ベベル（アルファ）と同じ約束） |
| softness | 0〜40 px | 2 | 傾きを取る前のぼかしの σ |
| strength | 0〜1 | 0.8 | ハイライト/シャドウ共通の強さ |

### 放射ブラー `radialBlur` — 中心点からの放射方向ブラー

| キー | 範囲 | 既定 | 意味 |
|---|---|---|---|
| amount | 0〜100 | 0 | ブラーの量。0 = 何もしない |
| centerX / centerY | 0〜1 | 0.5 | 中心点（クリップ枠に対する割合。Y は画面の上が 0） |
| mode | 0 / 1 | 0 | 方式。0 = ズーム（放射方向）、1 = 回転 |

px の引数は既存エフェクトと同じく 1920×1080 基準で、描画時に解像度へ拡縮される
（放射ブラーの量は割合ベースのため拡縮しない。中心からの距離そのものが解像度で伸びる）。

## 方式（ベベル共通基盤 `Bevel`）

1. 場（field）を作る。ベベル（アルファ）はアルファそのもの、ベベル＆エンボスは輝度（Rec.709）。
   どちらも「高い所ほど手前」とみなせる単一チャンネルの絵に直す。
2. 場を softness でぼかし、光の方向へ進んだ位置で読んだもの（S+）と逆のもの（S−）を作る。
   読みずらしの量が size / depth。ずらして読む元は端を延ばした絵なので、
   絵の境界そのものは輪郭にならない（全面不透明で平らな絵は画素一致のまま）。
3. ハイライト = clamp(S− − S+)、シャドウ = clamp(S+ − S−)（方向微分 −(∇場 · 光方向) の符号分割。
   減算は `CISubtractBlendMode` = clamp(背景 − 前景)、実測で確認）。平らな所では両方とも 0。
4. ハイライトは白・シャドウは黒のシルエット（アルファ = マスク × 強さ）にし、
   元のアルファの内側だけに絞ってから重ねる。ベベルは輪郭の内側だけに付き、シルエットは広がらない。
   輝度場の差は小さいため、エンボス側はマスクを内部で 2.5 倍に持ち上げる（`Bevel.luminanceGain`）。

放射ブラーのズーム方式は、中心のまわりに少しずつ拡縮したコピーを 12 枚均等に足し合わせる
（量 100 で拡縮 ±30%）。端は延ばして読む。回転方式は既存の `SpinBlur` に委譲し、量 100 を 90° に写す。

## Bevel Alpha と Bevel & Emboss の違い（対象の取り方）

- ベベル（アルファ）: 場 = アルファ。絵の中身（色・模様）には反応せず、透明/不透明の輪郭だけに斜面が付く。
  文字・図形・切り抜き素材向け。全面不透明で平らな絵では何も起きない。
- ベベル＆エンボス: 場 = 輝度。不透明な映像の明暗の段差（被写体の輪郭・模様）に浮き出しが付く。
  透明な所は輝度 0 として扱われるため、アルファ形状の縁にも（暗い地との段差として）反応するが、
  明るい絵が透明に接する縁では段差が小さく、ベベル（アルファ）ほどはっきり出ない。
  半透明の所の傾きは、見た目ではなく元の色（非乗算済み）の輝度で決まる。

## Premiere との違い・割り切り（正直な仕様）

- 厳密な再現ではない。Premiere の Bevel Alpha にある「輪郭（内側/外側/両方）」「光の高度」
  「斜面の種類」に相当するものは無い。本実装のベベルは常に輪郭の内側のみで、
  斜面の形はぼかした場の方向微分による近似（Premiere のような面の角度を持った斜面ではない）。
- Bevel & Emboss も、Premiere（レイヤースタイル系）のテクスチャ・輪郭カーブ・グロス等は無く、
  輝度の方向微分による浮き出しのみ。
- Radial Blur は Premiere の品質設定（草案/良好/最良）に相当するものは無く、サンプル数は固定 12。
  回転方式の量の写像（100 → 90°）は本アプリ独自の割り切り。
- 既定値の割り切り: 3 種とも「追加しただけでは絵が変わらない」（厚み/深さ/量の既定が 0 = 恒等）。
  既存エフェクトの多く（明るさ等、既定で効く）とは違うが、棚卸し課題の指定
  （既定値で恒等）に従った。効かせたいときは厚み/深さ/量を上げる。
- 追加方式の原則どおり、エフェクトが無い／無効／恒等値のクリップは従来と完全一致
  （`EffectPipeline.isIdentity` で解決時に落とされ、速い道のまま）。既存エフェクトの処理は無変更。

## 未検証事項

- Premiere 実機との見た目の一致は未検証（方式自体が近似で、上記の割り切りの範囲で妥当と判断）。
- GUI 実操作（インスペクタのスライダー・方式ラベル「ズーム/回転」の表示、メニューからの追加）は
  自動テスト（App スイートのメニュー構成テスト）までで、実機の目視確認は未実施。
- 実写素材・4K での描画速度は未検証。多重サンプル系（放射ブラーのズームは 12 枚、
  ベベルは場の生成＋ぼかし 1 回＋合成数回）で、重さは絞りぼかしと同程度の見込み。
- ベベルのハイライト/シャドウはリニア空間で計算されるため、sRGB の見た目では
  中間調の縁ほど明暗が強めに出る（テストはレンダリング後の画素で担保）。
