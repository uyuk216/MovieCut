# AIテキスト生成(W3-08)と話者分離(W3-27)

YMM4 監査 #74(AIテキスト生成)・#75(話者分離)への対応。実装はブランチ
`feat/ai-text-diarization`。

## W3-08 AIテキスト生成(#74)

台本作りの支援。テーマやキーワードからセリフ案を生成し、選んで台本へ取り込める。

### 導線

- 台本欄(左パネル)の「AIでセリフ案を作る…」ボタン
- 台本編集ウィンドウ(クリップ ▸ 台本を編集…)の「AIでセリフ案…」ボタン
- クリップ ▸ AIでセリフ案を作る…

シートでテーマ・キーワード・件数を指定して生成し、出た案にチェックを入れて
「台本欄へ取り込む」。取り込みは **Undo 1 回** で戻せる(台本編集ウィンドウの保存と
同じ作法)。今の台本の末尾は、続きを作るための参考としてプロンプトに含める。
生成しただけでは台本も音声も変わらない。

### プロバイダ境界と初期実装

- 生成は Core の `TextGenerationProvider` プロトコルの境界の後ろにある
  (プラグイン機構と同じ流儀で差し替え可能)。
- 初期実装は `OpenAICompatibleTextProvider`: ユーザーが設定したエンドポイントへ
  OpenAI 互換 chat completions 形式で送る汎用クライアント。通信は
  `TextGenerationTransport` 境界の後ろにあり、テストでは差し替えられる。
- テスト用モック `FakeTextGenerationProvider` で、生成 → 選択 → 取り込みの
  流れを通しで検証している。

### 設定と認証情報の扱い

- 接続情報(エンドポイント URL・モデル名・APIキー)は、ユーザー自身が
  ファイル ▸ AIテキスト生成の設定… で入れる。保存先はこの Mac のアプリ設定
  (UserDefaults)だけで、**プロジェクトファイルには書かない**。コード・テストにも
  認証情報は含めない。
- **未設定のときは機能が無効**で、シートとエラー表示にその旨が出る
  (`TextGenerationSettings.isConfigured` / `makeProvider()` の `notConfigured`)。
- http で送れるのはこの Mac 自身(localhost)宛てだけ。外部サービスは https 必須
  (平文でキーや台本を送らないため)。

### 実サービスとの確認状況

- **実サービスとの疎通確認は未実施**(認証情報を扱わない範囲では実施できない)。
  担保しているのは、未設定時の無効化とエラー表示、モック応答での生成 → 取り込み
  フロー、汎用クライアントの要求/応答形式(通信差し替えでの単体テスト)まで。
  実際のサービスで使う場合は、設定画面で接続情報を入れて確認すること。

## W3-27 話者分離(#75)

文字起こし(音声認識 / Whisper)の区間結果に話者ラベル(話者1・話者2…)を付ける。

### 導線

- クリップ ▸ 話者分離…(選んでいる音のあるクリップが対象。文字起こしと同じ条件)

シートで認識エンジン(音声認識 / Whisper)と話者数の上限(1〜8)を選び、
区間ごとのラベルを確認・手直ししてから反映する。反映先は 3 つで、どれも Undo 1 回。

- 「字幕を作る」: ラベルつき字幕(「話者1：本文」)を字幕レイヤーに新規作成
- 「既存の字幕に付ける」: 時刻と文が合う既存の文字クリップにラベルを付与
- 「台本欄へ送る」: 「話者1: 本文」の行を台本欄へ追加

「分け直す」は再認識せず、保存済みの特徴から上限だけ変えて分け直す。

### 方式

実用的な話者埋め込みモデルは同梱できないため、到達範囲として **音響特徴による
簡易判定** を実装した(Core `AcousticFeatureExtractor` / `AcousticClusterDiarizer`)。

- 区間ごとに、基本周波数(F0。自己相関で推定)・F0 のばらつき・音量(RMS)・
  スペクトル重心・帯域ごとのエネルギー配分(500Hz / 1500Hz / 3000Hz で
  区切った 4 帯域)・ゼロ交差率を測る。
- 時刻順に貪欲クラスタリング: 既存話者の重心との正規化距離がしきい値以内なら
  同じ話者、遠ければ新しい話者(上限到達時は最も近い話者へ寄せる)。
  声の高さを最も重く見る。音量は同一話者でも大きく変わるため同一性の判定
  には使わず、無音の判定だけに使う。決定的(同じ入力 → 同じ結果)。
- R6-1 の精度改善(音響特徴の枠組みの中での改善で、学習型ではない):
  - F0 のばらつき(抑揚)と帯域配分を距離に追加(従来は F0 のばらつきを
    測っていながら使っていなかった。帯域配分は重心だけでは分からない
    声質の形の目安)。
  - 無音区間と短すぎる区間(0.25 秒未満)は新しい話者を作らず直前の話者に
    寄せ、重心の計算にも混ぜない(特徴が不安定で重心を汚すため)。
  - 重心は区間の長さで重み付けする。最後に、頼れる区間だけで重心を
    作り直して 1 回だけ付け替え直し、重心どうしが近いクラスタは統合する。
  - 精度は合成シナリオのベンチマーク(`SpeakerDiarizationBenchmarkTests`、
    特徴と正解が既知の 7 シナリオ)で測っている: 改善前の平均ペアワイズ F1
    0.719 → 改善後 1.000。ただしこれは合成データでの数値で、実音声での
    分離精度を保証するものではない。
- 判定は `DiarizationEngine` プロトコルの境界の後ろにあり、将来の埋め込み型
  エンジンに差し替えられる。

### 限界(正直な明示)

- **学習型の話者埋め込みによる本格分離ではない**(未達)。同じ話者の声色の変化
  (叫ぶ・ささやく・風邪声など)や、似た声の別人を取り違えることがある。
- 無声区間や短すぎる区間は特徴が取れず、直前の話者に寄せる。このため、
  短い相槌のような短い区間の別話者は拾えないことがある。
- この限界はシート内の注意文(`SpeakerDiarizationInfo.limitationNotice`)でも
  利用者に明示している。ラベルは行ごとに手動で直せる前提の機能。

## 従来挙動との関係

どちらも追加方式で、新機能を使わない場合の挙動は従来と完全一致する。
内蔵の音声合成スタック(RealVoiceProvider 等)には触れていない。
プロジェクト形式への追加項目も無い(話者ラベルは字幕文・台本行の文字列として持つ)。
