# ベクトルスコープと RGB パレード

Premiere Pro の Lumetri スコープ相当として、既存の映像スコープ(ヒストグラム・輝度波形)に
ベクトルスコープと RGB パレードを追加した記録。棚卸し表のカラー節「Lumetri スコープ」の
不足分(ベクトルスコープ、パレード)への対応。

## 使い方

- 表示 ▸ スコープ… を開くと、今のプレビューのコマ(再生ヘッド位置)について、従来の
  ヒストグラム・波形の下に、ベクトルスコープと RGB パレードが並ぶ(シート内はスクロール)。
- 「更新」で現在のコマを取り直す。従来どおり表示用の sRGB 値で計算し、書き出しには影響しない。
- ベクトルスコープの読み方: 中心が無彩色、中心からの向きが色相、距離が彩度。
  オレンジの線はスキントーンライン(肌色が集まる目安の角度)、外周付近の R・M・B・C・G・Y の
  印は純色の位置。肌色が線から大きく外れていれば色かぶりの目安になる。
- RGB パレードの読み方: 画面の横位置ごとに R・G・B それぞれの明るさを並べたもの。
  3 枚の上下の広がりを見比べると、どの色がどこで強すぎるか・色かぶりが分かる。

## 実装

- Core(純粋な計算、画面なし):
  - `Sources/MovieCutCore/VectorScope.swift` — `VectorScope`
  - `Sources/MovieCutCore/RGBParade.swift` — `RGBParade`
  - 既存の `VideoScope`(ヒストグラム・波形)は無変更。濃さの対数圧縮は
    `VideoScope.intensity` を共用する。
- アプリ: `Sources/MovieCut/ScopeSheet.swift` が同じレンダリング済みコマから 3 種を計算し、
  既存のシート・更新タイミング(開いたときと「更新」)に乗せて表示する。

### ベクトルスコープの計算

表示用 sRGB 値(0〜255)を 0〜1 に直し、Rec.709 係数で輝度と色差を作る。

- Y = 0.2126 R + 0.7152 G + 0.0722 B
- Cb = (B − Y) / (2 × (1 − 0.0722))、Cr = (R − Y) / (2 × (1 − 0.2126))

画素ごとに (Cb, Cr) を 128 × 128 の密度グリッドへ数える。純色の位置は
赤 (−0.115, +0.500)、緑 (−0.385, −0.454)、青 (+0.500, −0.046)、黄 (−0.500, +0.046)、
シアン (+0.115, −0.500)、マゼンタ (+0.385, +0.454) で、単体テストで固定している。
スキントーンラインの角度 127° は、肌色の代表値(RGB 200・150・120 で約 128°、
180・120・90 で約 125°)の中央を取った目安であり、厳密な規格値ではない。

### RGB パレードの計算

横 256 列 × 縦 256 段を R・G・B 別々に数える。列は元画像の横位置に対応し
(既存波形と同じ `x × 列数 ÷ 幅`)、各チャンネルは自分の値の段にだけ数える。

## 計算の割り切り(正確さと速度のバランス)

- 間引き: ベクトルスコープ・パレードとも、画素数が上限 262,144 を超える場合は
  縦横同じ歩幅で等間隔に間引く(例: 1920×1080 ≒ 207 万画素なら歩幅 3 で約 23 万サンプル)。
  分布の形(色相・彩度の広がり、パレードの上下の広がり)は概ね保たれるが、
  ごく少数の画素しかない色や細い線状の色は落ちることがある。結果には
  `sampledCount` / `totalCount` / `stride` を残し、どれだけ間引いたか分かるようにした。
- 既存のヒストグラム・波形は従来どおり全画素で計算する(挙動を変えないため)。
  新スコープだけ間引くのは、シート表示の応答を優先した判断。
- 色空間: 既存スコープと同じく表示用 sRGB の符号化値が前提。HDR・Log の解釈や
  Rec.709 のスコープ規格(放送用の目盛り・IRE 表示など)は対象外。
- ベクトルスコープのグリッドは 128 × 128 で、表示専用の粗さ。計測器としての
  精密測定ではなく、色の偏りの目視確認が目的。

## テスト

- `Tests/MovieCutCoreTests/VectorScopeTests.swift`(13 件): 純色 6 色の座標(手計算と照合)、
  グレーの無彩色、彩度と半径の関係、肌色とスキントーンライン、グリッドのマス対応、

  純赤が他チャンネルへ混ざらないこと、左右での列対応、勾配、間引き、CGImage 経路、不正入力。
