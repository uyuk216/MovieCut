# スライド編集・J/Lカット・Premiere互換プリセット

Premiere Pro 棚卸し表(`premiere-inventory.md` 編集節)の「要確認」3件について、ソースで現状を確認した結果と、追加した実装の使い方をまとめる。いずれも追加・拡張のみで、既存操作の挙動は変えていない。すべての編集は Undo 1 回で戻せる。

## 1. スライド編集 — 無かった → 実装した

### 確認結果
- ロール編集・スリップ編集は `Sources/MovieCutCore/ClipRollSlip.swift` に実装済みだったが、スライド専用操作(ドラッグ・数値指定とも)は無かった。`slide` の名はトランジションや登場プリセットの種類としてだけ存在した。

### 実装
- Core: `ClipRollSlip.slide(in:clipId:deltaT:)` / `(in:clipId:frames:)` と `slideBlockedReason(in:clipId:)` を追加。
  - 前後のクリップにぴったり挟まれたクリップだけが対象。真ん中のクリップの位置だけが動き、長さと使う素材の区間(offset)は変わらない。前のクリップの終わりと後ろのクリップの頭が同じ量だけ連動する。
  - 止まる条件はロールと同じ規則: 前のクリップの素材の終わり、後ろのクリップの素材の頭、どちらかの最短の長さ(0.05 秒)。両側が動けた量の小さい方に合わせるので、3 本のつながりは崩れない。ロックされたクリップ・レイヤーは断る。動かせない・変わらないときは nil(Undo に載せない)。
- アプリ: クリップ ▸ スライド編集…(シートでコマ数を指定)と、タイムラインでクリップ本体を ⌥ ドラッグ。
  - ドラッグの割り当ては、ロール = ⌥ + 端、スリップ = ⌥⇧ + 本体、スライド = ⌥ + 本体。スライドできないクリップ(前後に挟まれていない・ロック)では従来どおりの操作に任せる。

## 2. J/Lカット — 専用操作は無かった → 実装した

### 確認結果
- 映像クリップは音声を内包する形で、映像と音声を別々にずらす機構は無かった。ロール/スリップ/音声だけのトリムで近づけることはできたが、J/Lカット専用の操作は無かった(機能調査の突き合わせでも「不明・確認できず」)。

### 実装の考え方
- MovieCut で映像と音が分かれている代表形は「映像レイヤー + 音声/ボイスレイヤー」。そこで、映像の境界はそのままに、音だけのクリップ(音声・ボイス)同士の境界だけをロールする専用操作として実装した。
- Core: `Sources/MovieCutCore/ClipSplitEdit.swift`(`ClipSplitEdit.splitEdit(in:anchorClipId:deltaT:)` / `(in:anchorClipId:frames:)`、`splitEditBlockedReason`)。
  - アンカーは境界の前後のどのクリップでもよい(映像側でも音側でも可)。アンカーの境界(終わり側を優先)と同じ時刻に、映像クリップ同士の境界と音だけのクリップ同士の境界の両方があるときだけ成立する。どちらか欠ければ nil(近似操作には倒さない)。
  - 正の量 = Lカット(前の音が映像の切り替わりの後まで残る)、負の量 = Jカット(次の音が映像より先に出る)。素材の範囲・最短の長さで止まるのはロールと同じ。
  - 映像クリップに内包された音声そのものを映像からずらす形(音声オフセットを別に持つ形)は、ファイル形式の変更になるため今回は見送った。必要になったら `Clip` に音声専用 offset を足す形で別途設計する。
- アプリ: クリップ ▸ J/Lカット…(シートでコマ数を指定。正 = L、負 = J)。Undo の名前も Jカット / Lカットになる。

## 3. Premiere互換キーバインドプリセット — 無かった → 実装した

### 確認結果
- ショートカットカスタマイズ自体は実装済みだった(`ShortcutStore` / `ShortcutSheet` / `KeyRouter.effectiveKeyMap`)。プリセットの仕組みは無かった。
- 既定の時点で Premiere Pro と同じもの: Space = 再生/停止、J/K/L = シャトル、←/→ = 1 コマ移動、⌘I = 素材を追加(Premiere の読み込み)、⌘+ / ⌘- = 拡大/縮小。これらはプリセットに含めていない。

### 実装
- `ShortcutStore.applyPremierePreset()` / `restorePrePresetBackup()` / `isPremierePresetApplied` / `hasPrePresetBackup` を追加し、ショートカット一覧シート(ヘルプ ▸ キーボードショートカット一覧)に「Premiere互換プリセットを適用」ボタンを置いた。
- プリセットの中身(Premiere Pro の主要キー割り当て):
  - C = クリップを分割(レーザーツール)
  - I = 書き出し開始を現在位置に / O = 書き出し終了を現在位置に(イン点・アウト点)
  - Q = リップルトリム(頭)を再生位置へ / W = リップルトリム(尻)を再生位置へ
  - ⌘K = クリップを分割(編集点を追加)
  - ⇧⌫ = すき間を詰めて削除(リップル削除)
- I / O / Q / W は、通常キーの受け口(`KeyCommand.markIn` / `markOut` / `rippleHead` / `rippleTail`)を新設して受けている。既定ではキーなしで、プリセット適用か個別の変更でのみ効く。テキスト入力中は通常キー全体が無効になる既存の仕組みの対象なので、入力欄で I や Q を打っても誤作動しない。
- 既存のユーザーカスタムは壊さない:
  - プリセットが書き換えるのは上の 7 件だけで、それ以外の割り当てはそのまま残る。
  - 初めて適用するときに限り、適用前の割り当て全体を控えておき、「プリセット適用前に戻す」で丸ごと戻せる(控えは 1 世代だけ。再適用しても控えは最初の適用前のまま)。
  - 「すべて既定に戻す」でも従来どおり全部戻せる。
