# 放送・配信用字幕形式(SCC / EBU-STL)

内部表現(`SubtitleFile` のキュー列)から、放送・配信用の字幕形式へ書き出す機能の説明。
対応コードは `Sources/MovieCutCore/BroadcastSubtitles.swift`、テストは `Tests/MovieCutCoreTests/BroadcastSubtitleTests.swift`。

## 対応形式

| 形式 | 状態 | 書き出し方 |
|---|---|---|
| SRT / WebVTT | 従来どおり(変更なし) | 字幕を書き出す… / CLI `subs` |
| SCC(Scenarist Closed Caption) | **新規対応** | 同上。保存パネルで `.scc` を選ぶ |
| EBU-STL(EBU Tech 3264) | **新規対応** | 同上。保存パネルで `.stl` を選ぶ |
| MCC(MacCaption / CEA-708) | **見送り**(理由は末尾) | — |
| MP4 への字幕トラック埋め込み | 未対応(本作業の範囲外) | — |

書き出し導線は従来と同じ「出力 ▸ 字幕を書き出す…」と CLI の `subs` コマンド。
拡張子で形式を判定する。STL はプロジェクトの fps が 27.5 未満なら STL25.01、以上なら STL30.01 を選ぶ。
変換時に置き換え・分割・遅延が起きたら、画面の状態欄と CLI の標準出力に注意として出す(黙って落とさない)。

## SCC

### 仕様の出典

- SCC ファイル形式(ヘッダ `Scenarist_SCC V1.0`、タブ区切り、16 進ワード列、制御コードの二重送信、奇数パリティ):
  Closed Caption Creator「SCC File Format Explained」 https://www.closedcaptioncreator.com/blog/articles/scc-file-format-explained.html
- CEA-608 の文字表(基本/特殊/拡張)、制御コード(ENM `94ae` / RCL `9420` / EDM `942c` / EOC `942f`)、PAC 表、Tab Over:
  McPoodle の SCC Tools 資料の転載 https://broadcastwriter.com/2023/03/17/the-scc-reader-in-me/
  (元の仕様は ANSI/CTA-608-E。デコーダ要件は 47 CFR 15.119 にも公開されている)
- パリティとバイト列の実例("HELLO" → `c845 4c4c 4f80`): Closed Captions: A Field Guide https://media.streamrolling.net/captions.html

### 実装の決めごと

- チャンネルは CC1、方式は pop-on(事前に作って一括表示。収録番組の標準)、位置は下寄せ・中央。行は最大 4 行まで画面の下から詰める。
- フレームレートは形式の性質上 **29.97fps(30000/1001)固定**。プロジェクトの fps が違っても SCC の時刻は 29.97 で数える
  (25fps の素材に SCC は不向き。その場合は EBU-STL を使うこと)。
- タイムコードは既定で**ドロップフレーム**(フレーム番号の区切りが `;`)。1 分ごと(10 分ごとを除く)に番号 00/01 を飛ばす
  換算を `SCCExporter.timecode(frame:dropFrame:)` に実装し、単体テストで境界(00:01:00;02 / 00:10:00;00)を確認している。
  ノンドロップは `SCCOptions(dropFrame: false)` で選べる(UI からは DF 固定)。
- 送信帯域は 2 バイト/フレームしかないため、各字幕は「表示フレームまでに裏バッファへの読み込みが終わる」よう
  逆算して読み込み開始を置く。前の字幕が表示中でも裏バッファには読み込めるので、読み込み同士の重なりだけを避ける。
  間に合わない字幕は表示を遅らせ、その件数を警告する。
- 消去(EDM)は、次の字幕の読み込みとぶつからない隙間があるときだけ終了フレームに出す。次の字幕がすぐ続く場合は
  その EOC(表示の入れ替え)で画面が切り替わるので EDM は出さない。最後の字幕には必ず EDM を出す。

### CEA-608 の制約と割り切り

- 文字: 表せるのは基本文字(ASCII の一部と á é í ó ú ç ÷ Ñ ñ)、特殊文字(® ° ½ ¿ ™ ¢ £ ♪ à è â ê î ô û)、
  拡張文字(À〜ø、句読点・記号類)のみ。**日本語・中国語・韓国語などは原理的に載せられない**。
  表せない文字は `?` に置き換え、置き換えた文字数を警告する。全角英数記号は半角へ寄せ、`…` は `...` にする。
  ルビ(`SubtitleCue.ruby`)は SCC に書き方が無いので落とす(SRT と同じ扱い)。
- 行: 1 行 32 桁。語の途中で割らない折り返しをし、1 語自体が 32 桁を超えたら割る。
- 行数: 1 字幕 4 行まで。超えたキューは表示時間を等分して複数の字幕に分割し、警告する(切り捨てはしない)。
- 中央寄せは PAC の桁(4 桁単位)+ Tab Over(1〜3 桁)で表すため、1 桁単位の近似になる。

## EBU-STL

### 仕様の出典

- EBU Tech 3264(1991)「EBU Subtitling data exchange format」。GSI ブロック 1024 バイト + TTI ブロック 128 バイトの構成、
  GSI 各フィールドのオフセット(CPN 0 / DFC 3 / DSC 11 / CCT 12 / LC 14 / OPT 16 / CD 224 / TNB 238 / TNS 243 / MNC 251 / TCP 256 / TCF 264)、
  TTI の内訳(SGN 0 / SN 1-2 / EBN 3 / CS 4 / TCI 5-8 / TCO 9-12 / VP 13 / JC 14 / CF 15 / TF 16-127):
  Closed Caption Creator「EBU-STL & Teletext Subtitles」 https://www.closedcaptioncreator.com/blog/articles/ebu-stl-teletext-subtitles.html
  および Subtitld の形式解説 https://subtitld.org/formats/stl 、go-astisub / SubtitleForAndroid の実装解説(deepwiki)で相互確認した。
- 文字コード CCT 00 = ISO/IEC 6937(Latin)。アクセント付き文字は「ダイアクリティカルのバイト(0xC1〜0xCF)+ 基底文字」の
  2 バイトで表す: 同上ガイド、および ISO/IEC 6937 の解説 https://en.wikipedia.org/wiki/ISO/IEC_6937

### 実装の決めごと

- DSC は `0`(オープン字幕)。改行は `0x8A`、テキスト欄の余りは `0x8F` で埋める。就き位置は中央(JC=02)、
  位置は 23 行グリッドの下寄せ(VP = 24 − 行数)。
- フレームレートは **25 / 30 のみ**(DFC で `STL25.01` / `STL30.01` を宣言)。時刻は名目 fps でフレームに丸める。
  STL30.01 は 29.97fps 素材向けの宣言として使われるが、STL 自体にドロップフレームの概念は無く、
  29.97 の実時間に対して約 0.1% のずれが蓄積する点に注意(長時間番組では納品先の指定を確認すること)。
- 1 行 40 文字(MNC=40)で折り返す。テキスト欄は 1 ブロック 112 バイトまでで、超えた字幕は拡張ブロック(EBN)に分ける
  (最後のブロックの EBN = 0xFF)。ダイアクリティカル記号の 2 バイト組はブロック境界で割らない。
- SN(字幕番号)はリトルエンディアンの 2 バイトで書く。GSI の TNB(総ブロック数)/ TNS(総字幕数)は実数と一致させる。
- 言語コード(LC)は既定 `09`(英語)。EBU のコードでは日本語は `69` だが、下記のとおり日本語の本文自体は載せられない。
- 読み戻し(`EBUSTLExporter.parse`)も実装した。拡張ブロックの連結、コメントブロック(CF=1)の読み飛ばし、
  ISO 6937 の合成(基底文字+結合文字→ NFC)を行い、往復テストで確認している。アプリの「字幕を読み込む」導線にはまだ繋いでいない。

### ISO 6937 の制約と割り切り

- 表せるのは Latin 文字と一部の記号のみ。**日本語などは載せられない**ため、表せない文字は `?` に置き換えて警告する。
- アクセントは Unicode の分解(NFD)を使って「記号バイト + 基底文字」に変換する。対応する記号は
  grave / acute / circumflex / tilde / macron / breve / dot / diaeresis / ring / cedilla / double acute / ogonek / caron。
  組み合わせが ISO 6937 に無い文字(例: ß、€。ユーロ記号は規格が古く含まれない)は `?` になる。
- 1 バイトで書く補助集合は ¡ ¢ £ ± ¿ ¹ Æ æ のみ実装した。それ以外の補助集合の文字は `?` になる。

## MCC を見送った理由

- MCC は CEA-708 のキャプションデータに加えてファイルヘッダ(フレームレート、ドロップフラーム、開始タイムコード等)と
  708 サービスブロックの組み立てが必要で、公開資料だけでは放送納品に耐える検証(実デコーダ・納品チェッカでの確認)ができない。
  中途半端に出力して「対応済み」に見せるより、SCC(CC1 の 608 データが実務の互換範囲)と EBU-STL を確実に先に出す判断をした。
- 708 が必要な納品では、当面は SCC を外部の MCC 変換ツールへ渡す運用を想定する。再挑戦する場合は、
  CTA-708 仕様書と検証用デコーダの確保が前提。

## 未検証事項

- 実機の放送デコーダ・納品チェッカ(Subtitle Edit 等の外部ツール含む)での読み込み確認は未実施。
  単体テストでは、仕様書由来の既知バイト列(SCC の "HELLO"、PAC、特殊文字)、GSI/TTI のフィールド配置、
  自前パーサでの往復一致までを確認している。
- SCC の色・下線・イタリック(CEA-608 の mid-row コード等)は使っていない(白文字のみ)。
- EBU-STL のテレテキスト形式(DSC=1/2、テレテキスト制御コード、色)は未対応。オープン字幕(DSC=0)のみ。
