# 口パクの実音声連動(AquesTalk / COEIROINK / SHAREVOX)

VOICEVOX は /audio_query のモーラ長から口形タイミングを作り、`<WAV>.visemes.json`(サイドカー)に保存する。
モーラ長を返さないエンジンも、同じサイドカー形式で実音声ベースに寄せた。

## 方式(包絡ベースの按分)
1. 生成済み WAV(速度適用後・キャッシュ済みのもの)を読み、10ms 窓の RMS 包絡を作る。
2. 包絡ピークの 10% を閾値に発音区間を割る。0.12 秒未満の谷(促音・語中の落ち込み)は埋め、0.03 秒未満の発音は捨てる。
3. 読みを `LipSync.moras`(あいうえお+閉口。拗音・促音・長音は既存規則)でモーラ列にする。
4. 無音を除いた発音時間を連結してモーラ数で等分し、実時間へ戻す。無音をまたぐモーラは区間を分ける。閉口モーラ(ん・っ)は時間を持つが区間は出さない。
5. `VoicevoxMora.encodeSidecar` で書く。描画は従来どおり `RenderAssets.visemes` がサイドカーを読む(描画側の分岐なし)。

実装: `Sources/MovieCutCore/AudioMoraTiming.swift`。合成後に切り離して(`scheduleEnvelopeSidecar`)書く。既に有効なサイドカーがあれば何もしない。

## 対象
AquesTalk(内蔵・プラグイン・say 代用)、COEIROINK v1 / SHAREVOX(VOICEVOX 互換系)、COEIROINK v2。
VOICEVOX は従来どおりモーラ長ベース(変更なし)。

## フォールバック
WAV が読めない・読みにモーラが無い・発音区間が無い場合はサイドカーを作らず、従来の推定(読みの長さと音量の積算)で動く。

## 限界
- モーラは等分。実際の長音・撥音・語頭の長さの差は反映しない。
- 子音の口形は持たない(母音と閉口のみ)。
- 発音区間が読みと大きくずれる音声(BGM 混入など)では精度が落ちる。
- COEIROINK / SHAREVOX は audio_query のモーラ長が使える版もあるが、v2 は無く、エンジンごとに差があるため共通の包絡方式にした。
