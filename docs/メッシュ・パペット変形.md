# メッシュ変形・パペット変形（W3-04 #55 / W3-05 #56）

2026-11-19 実装。ブランチ `feat/mesh-puppet`（base: `feat/muse-access` 8e81f98）。
2026-11-19 R2-5: プレビュー上のドラッグ編集とキーフレーム対応を追加。ブランチ `feat/warp-drag-keyframes`（base: `feat/muse-access` 865b04b）。

## 概要

- **メッシュ変形（#55）**: 列×行（2〜8、既定 3×3）の格子の制御点を元の位置からずらす変形。変位は格子点の変位を双線形補間した変位場で表す。
- **パペット変形（#56）**: ピン（可動/固定）を打ち、可動ピンの変位を距離の重み付き平均で周囲へ広げる変形（ボーンなしパペット）。重みは影響半径の内側で `(1 − (d/R)²)²`。固定ピンは変位 0 の重みとして分母にも入るため、その周りは動かなくなる（錨）。
- どちらも `Clip` の任意項目 `meshWarp` / `puppetWarp` として持つ。座標はクリップ自身の絵に対する割合（0〜1・左上原点）で、`ClipMask` と同じ約束。

## 描画手法の選定

採用: **変位場の逆写像サンプリング（CPU、双線形）**。出力の各画素について「その場所の変位を引いた元の位置」から色を取る。メッシュとパペットは変位場の作り方だけが違い、画素の移動は共通サンプラ `WarpRenderer`（`MeshPuppet.swift`）に一本化した（二重実装の回避）。

検討した代替案と不採用の理由:

- Core Image のビルトインフィルタ: 汎用のメッシュワープに相当するものが無い（`CIMeshGenerator` は模様生成用で、任意格子のワープではない）。
- `CIWarpKernel` のカスタムカーネル: 格子点の数が可変（最大 8×8=64 点）で、座標をカーネル引数へ載せる形が煩雑になる。パペットのピン（最大 32 本）も同様。
- 三角形分割＋アフィン変換の合成: セルごとの継ぎ目処理とマスク合成が複雑で、画素検証が難しくなる。

CPU サンプリングの利点は、画素単位で独立・決定的なこと（プレビューと書き出しで同じ結果、テストで方向性を厳密に検証できる）。代償として、大きな作業範囲では CIFilter より遅い（作業範囲の画素数に比例）。最適化（変位場の粗い格子への事前計算など）は将来課題。

描画の位置づけ: `Renderer.drawEffectedClip` の中で、クリップ自身の画素のスナップショットに対して**エフェクトより前**に適用する（変形した形にエフェクトが追従する）。作業範囲の余白には最大変位ぶんを加える。

## 後方互換

- 変形未設定（nil）のクリップはファイルに何も書かれず、描画も従来経路のまま（`Clip.hasActiveWarp` が false）。
- 設定があっても、全制御点が元の位置・全ピンの変位が 0（identity）なら描画経路をスキップし、画素は従来と完全一致する（テスト `testIdentityWarpRendersExactlyLikeNoWarp` で検証）。
- 読めない型の `meshWarp` / `puppetWarp` は捨てずに `extra` へ回して書き戻す。構造の中の知らないキーも保持する。
- 音声合成スタックには触れていない（速度 100 のバイト一致テスト群は全テストで確認）。

## 編集 UI の到達範囲

- インスペクタに「メッシュ変形」「パペット変形」の節を追加（`InspectorView.warpSections`）。
  - メッシュ: オン/オフ、列・行ステッパー、全制御点の横/縦スライダー＋「元に戻す」。
  - パペット: オン/オフ、ピンの追加（可動/固定、追加位置は中央）、影響半径スライダー、各ピンの横/縦スライダー、固定切替、削除。
  - すべて `ProjectModel+MeshPuppet` 経由で、離散操作・ドラッグとも Undo 1 回。
- **プレビュー上のドラッグ編集（R2-5 で実装）**: 選択中のクリップに変形があるとき、プレビューに取っ手を重ねて出す（メッシュは格子の線＋四角い制御点、パペットは丸いピン＋元の位置の小さい丸と結ぶ線、固定ピンは輪だけ）。
  - 取っ手は通常の移動・拡大・回転より優先して掴める。ドラッグは `beginGesture` 〜 `commitGesture` で Undo 1 回（座標変換と当たり判定は Core の `WarpDrag`、選択枠 `TransformBox` 基準）。
  - **ピンの任意位置への追加**: 選択中のクリップの中をダブルクリックすると、その場所にピンが増える（Shift+ダブルクリックで固定ピン）。パペット変形が無ければ用意からまとめて Undo 1 回。インスペクタの「中央に追加」も従来どおり使える。

## キーフレーム対応（R2-5 で実装）

- 項目名は `mesh.<番号>.x` / `mesh.<番号>.y` / `pin.<番号>.x` / `pin.<番号>.y`（`WarpKey`）。値は制御点・ピンの「現在の位置」の座標（割合）で、既存の `Clip.keyframes` にそのまま載る。補間・イージング・分割・トリム・フリーズフレームの焼き込みは既存の基盤（`Animation` / `KeyframeEditing`）がそのまま効く。
- 静的な値は従来どおり `meshWarp` / `puppetWarp` が持ち、キー評価の fallback になる（`Clip.staticValue(of:)` / `setStaticValue(_:of:)` が変形項目名を解釈）。**キーフレームの無いプロジェクトは、保存形式も描画も従来と同一**。
- 描画は時刻ごとに変形を評価する（`Clip.meshWarp(at:)` / `puppetWarp(at:)` / `warpResolved(at:)`）。ある時刻に全点・全ピンが元の位置（identity）に評価されれば、その時刻は従来経路のまま画素完全一致。固定ピンはキーに関係なく動かない。
- 編集の書き込みはキー対応（`WarpEditing.setMeshPointKeyed` など）: その座標にキーがあれば再生ヘッドのキーを書き、無ければ静的な値を書く。インスペクタの各座標スライダーには ◇（キー追加/削除・前後のキー移動・イージング）も付いた。
- 構造変更とキーの追従: 格子の列・行を変えるとメッシュのキーは外れる（形は再標本化で引き継ぐ）。ピンを消すと後ろのピンのキーが詰まる。ピンを固定するとそのピンのキーは外れる。変形を外す・点を「元に戻す」と、対応するキーも外れる。

## 制限・留保

- パペットのピンの「元の位置」は追加した場所。プレビューのダブルクリックで任意の場所に打てるようになったが、打った後の元の位置だけを数値で打ち直すことはできない（横/縦スライダーは現在の位置）。打ち直しはピンを消して打ち直す。
- 変位は逆写像の近似（変位場を出力側で評価）なので、非常に大きな変位では折り返し（フォールド）が起きうる。位置の範囲（−1〜2）と合成変位のクランプ（±1.5）で破綻は抑えている（極端な変位のテストあり）。
- 回転したクリップでは、描画の変形の基準矩形は作業範囲内のコンテンツ矩形（`contentBounds` 由来の `localBounds`）である一方、プレビューの取っ手は選択枠（回転した矩形そのもの、`TransformBox`）基準で置くため、回転と変形を同時に強く使うと取っ手の位置と実際の変形にずれが出る場合がある（従来からの留保）。
- テキストクリップにも付けられる（描画済みビットマップが変形する）。
