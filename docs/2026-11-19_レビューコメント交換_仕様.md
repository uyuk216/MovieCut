# レビューコメント交換(Frame.io 等価のローカル実現)

タイムコード付きのレビューコメントをプロジェクトに保持し、交換用ファイルで
他の人・他の道具とやり取りする仕組み。Frame.io のようなクラウド共有そのものは
作らない(下記「Frame.io との違い・未対応事項」)。

実装: Core は `ReviewComments.swift`(`ReviewComment` / `ReviewCommentEditing` /
`ReviewCommentExchange`)、App は `ProjectModel+ReviewComments.swift` と
`ReviewCommentsSheet.swift`、プロジェクトへの保持は `Project.reviewComments`。

## 使い方

- アプリ:移動 ▸「レビューコメントを追加…」/「レビューコメント一覧…」でシートを開く。
  - シート上部:作成者名と本文を入れて「追加」で、現在の再生位置にコメントが付く。
    選択中のクリップがあれば、そのクリップの id が対象として記録される。
    作成者名は端末内にだけ前回値を残し(プロジェクトには書かない)、次回も引き継ぐ。
  - 一覧の各行:タイムコードを押すとその位置へ移動、本文は編集して確定(Enter か
    フォーカスを離す)すると反映、解決済み/未解決の切り替え、削除ができる。
    すべて Undo 1 回で戻せる。
  - 「未解決のみ表示」で未解決だけに絞れる。見出しに総件数と未解決の件数が出る。
  - 移動メニューの「レビューコメント」サブメニューからも各コメントへ移動できる
    (解決済みにはチェックが付く)。
- 交換:移動 ▸「レビューコメントを書き出す…」(JSON / CSV)、
  「レビューコメントを読み込む…」(JSON / CSV)。シート下部のボタンからも開ける。
  - 書き出し先に `.csv` を選ぶと CSV、それ以外は JSON になる。
  - 読み込みはファイルの中身から形式を判定する(拡張子に依存しない)。
    大きさの上限は 8 MB。読み込みは 1 回の Undo で戻せる。

## 保存形式(プロジェクト内)

- `Project.reviewComments`(配列)。空のときはキーごと書かないので、
  コメントを使っていないプロジェクトのファイルは従来とバイト単位で一致する。
- 各コメントの項目:
  - `id`(文字列、必須)、`time`(秒、0 以上)、`body`(本文)
  - `endTime`(秒、任意。範囲コメントの終わり。`time` 以下なら読み捨てる)
  - `author`(作成者名、任意。空なら書かない。アカウント情報ではない表示名)
  - `clipId`(対象クリップの id、任意。クリップが消えてもコメントは残る)
  - `resolved`(解決済み。false なら書かない)
  - `createdAt` / `updatedAt`(ISO 8601 文字列、任意)
- マーカーと同じ作法:型が違う値は既定値に倒し、知らないキーは保持して書き戻す。
  コメント全体が型違いの場合はプロジェクトの `extra` に保持する。
- 安全策(読み込み時。正常な値は変えない):
  - 件数の上限 10,000 件、本文 4,000 文字、作成者名 100 文字(超えた分は切る)。
  - 時刻は 0 〜 360,000 秒(100 時間)に収める(`InputLimits` の sanitize)。
    範囲の終わりが開始以下になったら範囲なしに倒す。

## 交換ファイルの仕様

### JSON(正形式)

```json
{
  "format": "moviecut-review-comments",
  "version": 1,
  "exportedAt": "2026-11-19T12:00:00Z",
  "comments": [ { "id": "…", "time": 12.5, "body": "…", "author": "…" } ]
}
```

- コメントの各項目はプロジェクト内の保存形式と同じ(未知のキーも往復で保持する)。
- 読み込みは、素の配列 `[ {…}, … ]` だけの JSON も受け付ける
  (他の道具が作った一覧を取り込めるように)。
- `format` が違うファイル、`version` が 1 より大きいファイルは、黙って空にせず
  エラーとして断る(新しい形式の場合はバージョン番号を理由に出す)。

### CSV(読み書き両用)

- 列:`id,timecode,time,endTime,author,resolved,clipId,body`
- 書き出しは既存の CSV(使用クリップ一覧・注記一覧)と同じ作法:
  先頭に UTF-8 の BOM、行末は CRLF、引用は RFC 4180 式
  (カンマ・引用符・改行を含む項目は `"` で囲み、`"` は二重化)。
- `timecode` は `m:ss`(1 時間以上は `h:mm:ss`、秒未満は切り捨て)の表示用で、
  正確な時刻は `time` 列(秒)が持つ。`resolved` は `resolved` / `open`。
- 読み込み:見出し行があれば列名(英語・日本語。例:タイムコード/作成者/本文/
  解決済み)で対応づけ、無ければ書き出しと同じ列順とみなす。
  `time` 列が読めなければ `timecode` 列から復元する
  (`65` / `65.5` / `1:05` / `1:02:03.5` の形に対応)。
  本文が空の行は捨て、`id` が無い行には新しい id を振る。
- CSV には `createdAt` / `updatedAt` と未知のキーが無いので、**往復の正は JSON**。
  CSV は表計算ソフトでの閲覧・簡易な受け渡し用と位置づける。

### 読み込み時の競合規則

- 同じ `id` が既にある → 読み込んだ側で**上書き**(更新として数える)。
- 新しい `id` → **追加**。
- 交換ファイルに無い既存コメントは**消さない**。
- 内容がまったく同じ `id` は「変更なし」に数え、プロジェクトも Undo 歩数も変えない
  (同じファイルの再読み込みは冪等)。
- 反映後は時刻順に並べ直す。件数(追加・更新・変更なし)は状態欄に表示する。

## 設計判断(WIP からの変更点)

- CSV を「書き出し専用」から読み書き両用に広げた(元の要件「JSON を正とし、
  可能なら CSV も」への対応)。往復の正が JSON である点は変えていない。
- CSV のバイト作法を既存の書き出しに統一した(BOM・CRLF・`ClipListingExport.csvCell`
  の再利用。WIP 時点は BOM なし・LF のみだった)。
- 読み込み時の安全策(件数・長さ・時刻の上限)を追加した(他の入力形式の作法に倣う)。
- メニューの置き場所は WIP の判断(移動メニュー、マーカーの隣)をそのまま採用した。
  時間軸上の移動・一覧という性格がマーカーと同種のため。

## Frame.io との違い・未対応事項(保留事項)

- **クラウド共有はしない**:コメントはプロジェクトファイルと交換ファイルの中だけに
  あり、外部サービスへの自動送信・同期は一切しない
  (ユーザーのサーバに個人情報を持たせない大原則に従う)。
  作成者名などの個人情報もプロジェクト内のみで、外部送信はしない。
- **リアルタイム共同編集・同時接続は対象外**。受け渡しはファイル単位で、
  競合は上記の id 単位の規則で解決する(本文のマージはしない)。
- コメントへの返信(スレッド)、メンション、通知、承認ワークフローは未対応。
- 動画そのものへの描き込み(フレームへの図形注釈)は未対応。位置はタイムコードと
  対象クリップ id で表す。
- 範囲コメント(`endTime`)は保存・交換には対応するが、シートから範囲を指定して
  追加する操作は未対応(追加は再生位置の 1 点のみ)。
- 時刻・作成者名の編集はシート未対応(本文の編集のみ)。Core の編集計算にも
  時刻移動・作成者変更は無い(必要になったら `ReviewCommentEditing` に足す)。
- Frame.io 等の他サービスの形式との直接互換はない。取り込みたい場合は
  上記 JSON 形式(または素の配列・CSV)に変換してから読み込む。
- 他の道具・実機での検証は未実施(統括の Mac 検証待ち)。保証範囲は
  MovieCut 同士の往復と、仕様どおりの構造であることまで。
