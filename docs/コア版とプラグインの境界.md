# コア版とプラグインの境界メモ(実験ブランチ feat/core-plugin-split)

無料コアから音声合成エンジン接続(VOICEVOX / AquesTalk)を分離した実験の記録。
プラグインとして戻すときの接続点は次の通り。

## プラグインが実装するもの

- `VoiceProvider` プロトコル(Core に残置)の実装。合成して WAV を返し、`VoiceResult` を返す。
  - 台本の行解析・配置は Core の `ScriptTimeline.add(lines:to:voice:directory:selectedCharId:)` が担うので、
    プラグインは「1 キャラ × 1 行 → 音声ファイル」だけを実装すれば台本生成が成立する。
  - 既存クリップの作り直しも Core の自由関数 `regenerateVoice(clip:project:provider:)` が接着する。
- 話者一覧の取得と提示。元の `VoicevoxSpeaker` / `VoicevoxStyle` の形と、`SpeakerChoice.flatten` の
  ラベル化(話者名+スタイル名)はプラグイン側に置く。
- 依存チェック(エンジン導入・起動の検出。元の `DependencyStatus`)と、未導入時のバナー表示。
- 音声キャッシュ(元の `VoiceCache`。キー=エンジン/話者/パラメータ/テキスト)と、
  おすすめ音声設定の配布形式(元の `VoicePreset`、`docs/おすすめ音声設定の配布.md` の形式)。
- エンジンの起動管理(元の `VoicevoxEngine`)。アプリ終了時に止める接続点が要る(現行コアは終了処理を持たない)。
- AquesTalk の合成時変換: 声の表示名(新名)→プレイヤーの声名(旧名)の変換(元の `AquesTalkPresets.playerName`)。
  Core には読み込み互換のための正規化 `canonicalVoice` だけを残した。
- 試し読み上げ(プレビュー再生)と、代用エンジン(macOS の Kyoko 等)へ落ちたときの一度だけの知らせ。

## Core に残したもの(プラグインが読める前提)

- プロジェクトファイルのデータ: キャラの engine / speaker / voice / speed / pitch / intonation、
  プロジェクトの voicevoxUrl / aquestalkCommand フィールドはそのまま保存・読み込みされる(互換のため)。
  コア版ではこれらは「データとして保持するだけ」で、合成には使わない。
- `CharacterEditing.switchEngine`(エンジン切替時のパラメータ初期値)とフィールドの範囲クランプ。
- 字幕テキストの編集(`setVoiceSubtitleText`)、セリフ文字の編集(`setVoiceText` / `setVoiceCharacter` は
  コア版では再合成しない同期編集)。
- WAV の長さ読み `WavFile.duration(of:)`(書き出し・配置の尺計算に使う)。
- 声クリップの尺に後続を詰める純粋計算 `VoiceRipple`(適用の発火はプラグイン側の再合成と一体)。

## 判断が必要な境界(今回は残した/外した判断)

- `AquesTalkPresets.canonicalVoice`: 旧プロジェクトの声名(れいむ等)を新名へ直す読み込み互換として Core に残した。
- CLI の `script` コマンド: 台本→音声生成そのものなのでコア版 CLI からは外した(プロジェクト生成系は残置)。
- 初回ガイドの手順と台本欄の案内文は、コア版のワークフロー(素材追加→整形→字幕→書き出し)に書き換えた。

## 境界判断4点の作業決定(2026-11-18)

前回の検証で出した推奨を作業決定として記録する。いずれも 2026-11-18 のユーザーの「続けておいて」を受けて推奨どおり作業決定したものであり、覆す場合はユーザー判断による。

### ① 互換フィールドの残置 = A(現状維持、型付きで残置)

- プロジェクトの voicevoxUrl / aquestalkCommand、キャラの engine / speaker / voice / speed / pitch / intonation は、Core が型付きで保持し続ける(合成には使わない)。
- 理由: 既に「データ保持だけ」で害が小さい一方、プロジェクト互換はユーザー資産の保護に直結する。配布形式が固まったら、プラグイン所有セクションへ移す案(C)を再検討する。
- 2026-11-18 ユーザーの「続けておいて」を受けて推奨どおり作業決定。覆す場合はユーザー判断。

### ② canonicalVoice の置き場 = A(Core に維持)

- 旧名→新名の正規化(れいむ→女声1、まりさ→女声2)は、読み込み互換として Core に維持する。プラグイン未導入でも効くべきものだからである。
- 切り分け方針: 現行プリセット一覧(AquesTalkPresets.all)のような「現役の知識」は将来プラグイン側へ寄せ、Core には互換専用の正規化だけを残す。
- 2026-11-18 ユーザーの「続けておいて」を受けて推奨どおり作業決定。覆す場合はユーザー判断。

### ③ CLI script コマンドの扱い = 段階案(現状維持、必要になれば B)

- 当面は現状維持(A): script / speak / speakers / deps はコア版 CLI に戻さない。台本→音声はプラグイン側の担当とする。
- ユーザーの制作フロー(台本→プロジェクト生成)が実利用で止まる場合は、B(Core CLI に戻し、内部で PluginHost から解決する。プロバイダ未解決時は合成せず、台本だけのプロジェクト生成に落とすフォールバック付き)へ移行する。
- 2026-11-18 ユーザーの「続けておいて」を受けて推奨どおり作業決定。覆す場合はユーザー判断。

### ④ 初回ガイドの文案 = B(音声プラグイン導線の一節をコアに残す)

- コア版の初回ガイドは、コアのワークフロー(素材追加→整形→字幕→書き出し)を案内しつつ、「音声プラグインで台本から声が作れる」導線の一節だけを残す。
- 理由: 看板機能「台本→音声」がガイドから完全に消えると発見性が落ちる。文案はプラグイン未導入でも誤解のない表現とし、最終文案はユーザーが確認する前提。
- 2026-11-18 ユーザーの「続けておいて」を受けて推奨どおり作業決定。覆す場合はユーザー判断。本決定に基づき、導線の一節を初回ガイドへ実装した(同日の作業)。
