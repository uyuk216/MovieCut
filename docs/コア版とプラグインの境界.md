# コア版とプラグインの境界メモ(実験ブランチ feat/core-plugin-split)

無料コアから音声合成エンジン接続(VOICEVOX / AquesTalk)を分離した実験の記録。
プラグインとして戻すときの接続点は次の通り。

## プラグインが実装するもの

- `VoiceProvider` プロトコル(Core に残置)の実装。合成して WAV を返し、`VoiceResult` を返す。
  - 台本の行解析・配置は Core の `ScriptTimeline.add(lines:to:voice:directory:selectedCharId:)` が担うので、
    プラグインは「1 キャラ × 1 行 → 音声ファイル」だけを実装すれば台本生成が成立する。
  - 既存クリップの作り直しも Core の自由関数 `regenerateVoice(clip:project:provider:)` が接着する。
- 話者一覧の取得と提示。元の `VoicevoxSpeaker` / `VoicevoxStyle` の形と、`SpeakerChoice.flatten` の
  ラベル化(話者名+スタイル名)はプラグイン側に置く。
- 依存チェック(エンジン導入・起動の検出。元の `DependencyStatus`)と、未導入時のバナー表示。
- 音声キャッシュ(元の `VoiceCache`。キー=エンジン/話者/パラメータ/テキスト)と、
  おすすめ音声設定の配布形式(元の `VoicePreset`、`docs/おすすめ音声設定の配布.md` の形式)。
- エンジンの起動管理(元の `VoicevoxEngine`)。アプリ終了時に止める接続点が要る(現行コアは終了処理を持たない)。
- AquesTalk の合成時変換: 声の表示名(新名)→プレイヤーの声名(旧名)の変換(元の `AquesTalkPresets.playerName`)。
  Core には読み込み互換のための正規化 `canonicalVoice` だけを残した。
- 試し読み上げ(プレビュー再生)と、代用エンジン(macOS の Kyoko 等)へ落ちたときの一度だけの知らせ。

## Core に残したもの(プラグインが読める前提)

- プロジェクトファイルのデータ: キャラの engine / speaker / voice / speed / pitch / intonation、
  プロジェクトの voicevoxUrl / aquestalkCommand フィールドはそのまま保存・読み込みされる(互換のため)。
  コア版ではこれらは「データとして保持するだけ」で、合成には使わない。
- `CharacterEditing.switchEngine`(エンジン切替時のパラメータ初期値)とフィールドの範囲クランプ。
- 字幕テキストの編集(`setVoiceSubtitleText`)、セリフ文字の編集(`setVoiceText` / `setVoiceCharacter` は
  コア版では再合成しない同期編集)。
- WAV の長さ読み `WavFile.duration(of:)`(書き出し・配置の尺計算に使う)。
- 声クリップの尺に後続を詰める純粋計算 `VoiceRipple`(適用の発火はプラグイン側の再合成と一体)。

## 判断が必要な境界(今回は残した/外した判断)

- `AquesTalkPresets.canonicalVoice`: 旧プロジェクトの声名(れいむ等)を新名へ直す読み込み互換として Core に残した。
- CLI の `script` コマンド: 台本→音声生成そのものなのでコア版 CLI からは外した(プロジェクト生成系は残置)。
- 初回ガイドの手順と台本欄の案内文は、コア版のワークフロー(素材追加→整形→字幕→書き出し)に書き換えた。

## 境界判断4点の作業決定(2026-11-18)

前回の検証で出した推奨を作業決定として記録する。いずれも 2026-11-18 のユーザーの「続けておいて」を受けて推奨どおり作業決定したものであり、覆す場合はユーザー判断による。

### ① 互換フィールドの残置 = A(現状維持、型付きで残置)

- プロジェクトの voicevoxUrl / aquestalkCommand、キャラの engine / speaker / voice / speed / pitch / intonation は、Core が型付きで保持し続ける(合成には使わない)。
- 理由: 既に「データ保持だけ」で害が小さい一方、プロジェクト互換はユーザー資産の保護に直結する。配布形式が固まったら、プラグイン所有セクションへ移す案(C)を再検討する。
- 2026-11-18 ユーザーの「続けておいて」を受けて推奨どおり作業決定。覆す場合はユーザー判断。

### ② canonicalVoice の置き場 = A(Core に維持)

- 旧名→新名の正規化(れいむ→女声1、まりさ→女声2)は、読み込み互換として Core に維持する。プラグイン未導入でも効くべきものだからである。
- 切り分け方針: 現行プリセット一覧(AquesTalkPresets.all)のような「現役の知識」は将来プラグイン側へ寄せ、Core には互換専用の正規化だけを残す。
- 2026-11-18 ユーザーの「続けておいて」を受けて推奨どおり作業決定。覆す場合はユーザー判断。

### ③ CLI script コマンドの扱い = 段階案(現状維持、必要になれば B)

- 当面は現状維持(A): script / speak / speakers / deps はコア版 CLI に戻さない。台本→音声はプラグイン側の担当とする。
- ユーザーの制作フロー(台本→プロジェクト生成)が実利用で止まる場合は、B(Core CLI に戻し、内部で PluginHost から解決する。プロバイダ未解決時は合成せず、台本だけのプロジェクト生成に落とすフォールバック付き)へ移行する。
- 2026-11-18 ユーザーの「続けておいて」を受けて推奨どおり作業決定。覆す場合はユーザー判断。

### ④ 初回ガイドの文案 = B(音声プラグイン導線の一節をコアに残す)

- コア版の初回ガイドは、コアのワークフロー(素材追加→整形→字幕→書き出し)を案内しつつ、「音声プラグインで台本から声が作れる」導線の一節だけを残す。
- 理由: 看板機能「台本→音声」がガイドから完全に消えると発見性が落ちる。文案はプラグイン未導入でも誤解のない表現とし、最終文案はユーザーが確認する前提。
- 2026-11-18 ユーザーの「続けておいて」を受けて推奨どおり作業決定。覆す場合はユーザー判断。本決定に基づき、導線の一節を初回ガイドへ実装した(同日の作業)。

## 最初の実プラグイン: VOICEVOX の追加方式実装(2026-11-19、feat/voicevox-plugin)

- feat/plugin-foundation(コア分離実験)は本家へ統合しない判断のままである。本節は muse-access 側の話である。
- 基盤(PluginHost / PluginManifest / PluginDiscovery / LicenseVerifier)は、feat/plugin-foundation から追加分だけを取り込んだ。
- 最初の実プラグインとして VOICEVOX を「組み込みプラグイン」として実装した。プラグイン側クライアント(VoicevoxPluginClient)は内蔵 VoicevoxClient のロジックの複製で、内蔵側は無変更で残置されている。
- 接続は PluginVoiceRoutingProvider が担う: 担当プラグインが登録されていればプラグイン経路、無ければ・解決に失敗したら内蔵経路に落ちる。
- 内蔵音声スタックの削除と、プラグインの動的読み込み(バンドル/暗号化パッケージ配布)への移行は後続ステップ。現時点では「追加」であって「移行」ではない。

## 2つ目の実プラグイン: AquesTalk の追加方式実装(2026-11-19、feat/aquestalk-plugin)

- VOICEVOX と全く同じ「追加方式」で、2つ目の実プラグインとして AquesTalk を「組み込みプラグイン」として実装した。プラグイン側シンセサイザ(AquesTalkPluginSynthesizer)は内蔵 AquesTalkSynthesizer のロジックの複製で、内蔵側は無変更で残置されている。
- 接続は VOICEVOX と同じ PluginVoiceRoutingProvider が担う: engine が "aquestalk" のキャラはプラグイン経路、未登録・解決に失敗したら内蔵経路に落ちる。VOICEVOX 側の振り分けは従来どおり。
- Kyoko 代用警告(「AquesTalkPlayer が見つからないので Kyoko で代用した」お知らせ)は、プラグイン経路では内蔵 RealVoiceProvider の記録に残らないため、ルータの VoiceFallbackReporting 委譲を拡張し、読み込み済みの AquesTalk プラグインの enginesUsed も見るようにした。
- 速さの扱い(調査結果): キャラの speed は VOICEVOX = 倍率(標準 1、合成の speedScale に反映済み)、AquesTalk = %(標準 100。ゆっくり 130% は speed = 130 をキャラ/プリセットに持つ)で、どちらもインスペクタの「話す速さ」で変更でき、プロジェクトと音声プリセットに保存される。プラグインは speed を内蔵と寸分違わずそのまま渡す(独自に 1.3 倍へ変換しない。等価性はキャッシュキーの一致で担保)。
- ただし AquesTalk では、速さは現行ではキャッシュキーにのみ効き、生成される音声自体には反映されていない。AquesTalkPlayer のコマンドライン(-P / -T / -W のみ)に速さの指定が無いためである。音声へ反映するには、合成後の WAV への時間伸縮(音程保持)の後処理を、内蔵・プラグイン両方のシンセサイザへ対で追加する必要があり、内蔵の振る舞いを変える変更になるため、本ブランチ(内蔵無変更が前提)には含めていない。実施する場合は別ステップで、両経路同時に、速さ 100 では無変換(参照 WAV とのバイト一致テストを壊さないこと)を条件に行う。
- 内蔵音声スタックの削除と、プラグインの動的読み込みへの移行は VOICEVOX と同じく後続ステップ。現時点では「追加」であって「移行」ではない。

## AquesTalk の速さを音声へ反映(2026-11-19、feat/aquestalk-speed)

- 前節で「別ステップ」として予告していた件を実施した。**内蔵の振る舞いを変える変更**である(このブランチでは「内蔵無変更」の前提を意図的に外している)。理由: AquesTalkPlayer のコマンドライン(-P / -T / -W)に速さの指定が無く、引数経由では原理的に反映できないため。
- 方式: 共有の後処理部品 `VoiceTimeStretch` を新設し、内蔵 `AquesTalkSynthesizer` とプラグイン `AquesTalkPluginSynthesizer` の両方が、生成した WAV へ音程保持の時間伸縮をかけてからキャッシュへ置く。実装は `AudioRemap` の速度変換と同じ流儀(AVAudioEngine のオフラインレンダリング + `AVAudioUnitTimePitch`、出力は入力フレーム数 ÷ rate ちょうど、ユニットの遅れぶんは頭を捨てる)。速さは `Character.speed` の % 表記そのまま(130 → 尺が約 1/1.3)。
- 互換条件: 速さ 100 と未指定では後処理を通さず完全な無変換とし、実プレイヤーの参照 WAV とのバイト一致テスト(内蔵・プラグイン両方)を維持した。キャッシュキーは従来どおり速さを含むため、速さ違いは別キャッシュのまま(キーの変更なし)。
- say 代用経路の扱い: プレイヤーが無い環境の `say -v Kyoko` 代用にも同じ後処理を適用し、速さが効くようにした(従来は代用時も速さは音声に無効だった)。代用かどうかで速さの効き方が変わらないための判断で、100・未指定では代用時も無変換。

## プラグイン機構の拡張: エフェクト種別と書き出し種別(2026-11-19、feat/plugin-expansion、監査#76)

音声中心だったプラグイン機構を、YMM4 式の全面プラグイン化へ近づける第 2 波。いずれも「追加方式」で、プラグイン未登録時は従来動作と完全同一(テストで担保)。

### エフェクト種別(`hooks: [.effect]`)

- マニフェストに `effectIDs` を追加した(音声の `voiceEngineIDs` と同じ流儀。旧形式の manifest.json では空として読む)。識別子は `Effect.kind`(文字列)そのもので、内蔵 `EffectKind.rawValue` と衝突しないよう接頭辞付き(例: "plugin.invert")を約束とする。プロジェクトファイルにはこの文字列で保存され、プラグインが無い環境では従来どおり「知らない種類は何もしない」になる。
- 接続点は `VideoEffectProviding` プロトコル(記述子 `PluginEffectDescriptor` の宣言、恒等判定、CIImage → CIImage の同期適用)。引数の仕様は内蔵と同じ `EffectParamSpec` を使い、クランプ・既定値・キーフレーム("fx.<番号>.<引数名>")の流儀を揃えた。
- `EffectPipeline` に統合経路を追加した: `resolveAll`(内蔵 + プラグインをクリップの並び順を保って解決。結果は `ResolvedClipEffect`)と、その `apply`。従来の `resolve` / `apply` は無変更で、プラグインプロバイダが空なら統合経路も従来と完全同一。内蔵だが「何もしない値」のエフェクトはプラグインへ回さない(二重適用の防止)。プラグインエフェクトは絵の外へはみ出さない前提で、作業範囲の拡大(`margin`)には数えない。
- 解決は `PluginHost.effectProvider(forEffectID:)` / `effectProviderIfAvailable(forEffectID:)`(遅延読み込み・ライセンス検証は音声と同じ経路)。記述子は本体側にあるため、記述子一覧の取得は対象プラグインの実体化を伴う。
- サンプルの組み込みエフェクトプラグインを 2 個同梱した: 色反転 `InvertEffectPlugin`(識別子 "plugin.invert"、色行列で強さ混合)とポスタリゼーション `PosterizeEffectPlugin`(識別子 "plugin.posterize"、CIColorPosterize)。どちらも `AppServices.makePluginHost` に登録済みで、ホスト経由で解決・適用できる。
- 未達(正直な範囲): Renderer(プレビュー/書き出しの描画)への配線と、インスペクタ/メニューへのプラグインエフェクト表示はまだ行っていない。現時点では `EffectPipeline` の統合経路が「内蔵と同じ経路」であり、Renderer がプラグインプロバイダを受け取る配線は後続ステップ(既定では従来描画のまま)。

### 書き出し種別(`hooks: [.exporter]`)

- マニフェストに `exportFormatIDs` を追加した(例: ["gif"])。解決は `PluginHost.exportBackend(forFormat:)` / `exportBackendIfAvailable(forFormat:)`。
- 接続点は `ExportBackendProviding` プロトコル(形式記述子 `ExportFormatDescriptor` の宣言と、非同期の書き出し)。入力は内蔵書き出しと同じ部品(プロジェクト・`RenderAssets`・区間・進み具合コールバック)なので、既存の書き出し実装をそのまま包んでプラグイン化できる。
- 入口は `PluginExportJob.runIfAvailable`(音声の `PluginVoiceRoutingProvider` と同じ考え方): 担当プラグインがあればプラグイン経路で書き出し、未登録・解決失敗なら nil を返して呼び出し側が内蔵 `ExportJob` へ落とす。書き出し自体の失敗は黙って別形式に化けないよう、そのまま投げる。
- サンプルの組み込み書き出しプラグインを 2 個同梱した: `GIFExportPlugin`(形式 "gif"。内蔵 `GIFExporter` への委譲で「既存バックエンドのプラグイン化」を実証)と `ProjectInfoExportPlugin`(形式 "project-json"。描画しない軽量形式で、解像度・長さ・クリップ数の要約 JSON を決定的に書く)。どちらも `AppServices.makePluginHost` に登録済み。
- 未達: 書き出しシート/CLI がプラグイン形式を一覧・選択する UI 配線はまだ行っていない(境界と解決・実行の経路まで)。FFmpeg のような外部コマンド型バックエンドも、この境界にそのまま実装できる(入力がプロジェクト+出力 URL のため)。

### 作業決定(覆せる)

- フックの形: エフェクトは同期・画素単位(CIImage 変換)、書き出しは非同期・ファイル単位とした。プレビュー描画の最中に呼ばれるエフェクトで非同期は採れないため。
- パラメータの渡し方: エフェクトは記述子の `EffectParamSpec` で宣言し、解決時にクランプ+キーフレーム補間済みの `[String: Double]` を渡す(内蔵 `ResolvedEffect` と同形)。書き出しは型付きの引数(プロジェクト/素材/区間/出力先)のまま渡す。
- 識別子の置き場: 音声の `voiceEngineIDs` と対称に、マニフェストへ `effectIDs` / `exportFormatIDs` を追加した(プラグイン側の二重管理を避けるため)。

## 配線フォローアップ: Renderer・UI への配線(2026-11-19、feat/wiring-followups、バッチQ F-1)

前節で「未達」とした 2 点を配線した。いずれも追加方式で、プラグインプロバイダが空・未登録のときは従来と完全一致(テストで担保)。

- Renderer への配線: `Renderer` が `pluginEffectProviders`(既定は空)を受け取り、`EffectPipeline.resolveAll` / 統合版 `apply` で描くようにした。通常クリップ・調整レイヤー・複合/シーンの子 Renderer(引き継ぎ)すべてに効く。アプリ側は `AppServices.pluginEffectProviders`(組み込み分の静的一覧)をプレビュー(`PreviewView`)と書き出し(MP4 の `ExportJob`・キュー・GIF・APNG・連番PNG+WAV)に渡す。
- UI への配線(エフェクト): クリップメニュー「エフェクト」サブメニューとインスペクタの「＋追加」メニューに、プラグインのエフェクト(色反転・ポスタリゼーション)が並ぶ。追加は記述子の初期値で 1 回の Undo。付けたエフェクトはインスペクタで記述子の引数スライダーで編集でき、「初期値に戻す」も記述子で効く(`EffectEditing.reset(_:at:descriptor:)`)。
- UI への配線(書き出し): 出力メニューに「プラグイン形式で書き出す」サブメニューが付き、登録済み形式(GIF(プラグイン)・プロジェクト情報JSON)が選べる。実行は `PluginExportJob.runIfAvailable` で、担当が解決できない形式は黙って内蔵形式に化けずエラーにする。
- 留保: GIF プラグインバックエンド内部の描画(`GIFExporter` への委譲)には、他のプラグインのエフェクトプロバイダは渡していない(プラグイン同士の相互参照を避けるため)。MP4 など本体の書き出し経路ではプラグインエフェクトが効く。
