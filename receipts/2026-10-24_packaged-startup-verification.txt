Packaged Electron startup crash: 2026-10-24 (JST)

ROOT CAUSE
Electron 44.9.0 compares the resolved helper executable path byte-for-byte
against paths derived from CFBundleName before launching child processes.
Original CFBundleName used NFC (デ = U+30C7; UTF-8 e3 83 87), while the
helper executable paths used NFD (テ U+30C6 + U+3099; UTF-8 e3 83 86 e3 82 99).
MakeAbsoluteFilePath resolved the actual NFD filename, so CHECK_EQ(program,
child_path) in ElectronBrowserClient::AppendExtraCommandLineSwitches failed.
The silent brk #0 / exit 133 is this failed comparison, not the concurrently
running DNS resolver. LLDB captured both differing strings at that branch.

Primary source (Electron v44.9.0, lines 517-548):
https://github.com/electron/electron/blob/v44.9.0/shell/browser/electron_browser_client.cc#L517-L548
Helper path construction:
https://github.com/electron/electron/blob/v44.9.0/shell/app/electron_main_delegate_mac.mm#L27-L60

CONTROLLED EXPERIMENTS
1. Original saved Japanese bundle, unchanged application main.js: exit 133.
2. Same original bundle with minimal app.asar (no VOICEVOX/fetch/sysctl,
   protocol registration, BrowserWindow, or app.getPath): MINIMAL ENTER,
   then exit 133, before MINIMAL READY.
3. Same minimal bundle, re-signed in both cases; ONLY CFBundleName normalized
   to NFD: exit 0, MINIMAL ENTER then MINIMAL READY.
4. Same original full app, ONLY CFBundleName normalized to NFD and re-signed:
   exit 0, H.264/AAC MP4, duration 3.547667 seconds.
5. Changing only the main executable to ASCII, retaining original NFC
   CFBundleName and NFD helpers: still exit 133.
6. The partially edited current bundle had productName YukkuriEditor but
   extendInfo.CFBundleName in Japanese: exit 133 with FATAL "Unable to find
   helper app". Aligning only CFBundleName to YukkuriEditor launched for
   the full 12-second observation (timeout exit 124).

EXCLUDED CAUSES
Source and initial current packaged Electron Framework were byte-identical:

Both used Electron 44.9.0, with identical fuses:

EnableNodeOptionsEnvironmentVariable=enabled; EnableNodeCliInspectArguments=enabled;
EnableEmbeddedAsarIntegrityValidation=disabled; OnlyLoadAppFromAsar=disabled;
LoadBrowserProcessSpecificV8Snapshot=disabled; GrantFileProtocolExtraPrivileges=enabled.
The saved original framework was re-signed, so its full hash differed, but its
Mach-O UUID and framework version matched. Original saved app.asar main.js
and current packaged app.asar main.js both exactly matched project main.js.
macOS log show returned no useful app entries. LLDB, minimal reproduction,
and the one-field normalization experiment established the failure condition.

FIX
package.json:
- productName is Japanese in NFD, written as ゆっくりエテ\u3099ィタ to make
  the combining dakuten explicit. Keep it NFD when editing the product name.
- Remove the independent CFBundleName override; electron-builder now derives
  the bundle/helper/executable names consistently from that same productName.
- Keep user-visible CFBundleDisplayName as the conventional Japanese NFC name.
- mac.identity="-", hardenedRuntime=false, notarize=false for local ad-hoc signing.
- Keep the existing files allowlist; vendor/ remains excluded.
No application JavaScript, HTML, CSS, or package-lock.json changed.
